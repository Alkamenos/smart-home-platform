"""
АРХИТЕКТУРА КЭШИРОВАНИЯ И ИНДЕКСИРОВАНИЯ УСТРОЙСТВ

Описание решения
================

Реализовано двухуровневое решение для оптимизации производительности поиска устройств:
1. DeviceCache - LRU кэш с TTL для быстрого доступа к часто используемым устройствам
2. IndexManager - многомерное индексирование для быстрого поиска по различным критериям

Характеристики
==============

DeviceCache:
- LRU (Least Recently Used) вытеснение при достижении максимального размера
- TTL (Time-To-Live) для автоматического инвалидирования устаревших данных
- Максимум 1000 записей по умолчанию
- TTL 300 секунд по умолчанию
- Thread-safe операции с использованием RLock
- Метрики: cache_hits, cache_misses, cache_invalidations, hit_rate

IndexManager:
- Индексирование по source_id для быстрого поиска устройств от источника
- Индексирование по device_type для быстрого поиска устройств по типу
- Индексирование по ha_entity_id для уникального поиска по HA ID
- Индексирование по status для поиска доступных/недоступных устройств
- Thread-safe операции с использованием RLock
- Метрики: index_operations, index_errors, device_count

Интеграция в DeviceService
============================

Методы, использующие кэш и индекс:
- get_device(device_id) - проверяет кэш, затем индекс, затем основное хранилище
- get_devices_by_source(source_id) - использует индекс для быстрого поиска
- update_device_state(device_id, new_state) - инвалидирует кэш при изменении
- find_devices_by_type(device_type) - использует индекс для поиска по типу
- find_device_by_ha_entity_id(ha_entity_id) - использует индекс для поиска по HA ID

Методы управления кэшем и индексом:
- get_cache_stats() - получить статистику кэша
- get_index_stats() - получить статистику индекса
- clear_cache() - очистить весь кэш
- invalidate_device_cache(device_id) - инвалидировать кэш для устройства
- invalidate_source_cache(source_id) - инвалидировать кэш для всех устройств источника
- rebuild_index() - пересоздать индекс из всех устройств в памяти

Примеры использования
=====================

1. Получение устройства по ID:
   device = await device_service.get_device(device_id)
   # Сначала проверяется кэш, затем индекс, затем основное хранилище

2. Поиск всех устройств источника:
   devices = await device_service.get_devices_by_source(source_id)
   # Использует индекс для быстрого поиска

3. Поиск устройств по типу:
   lights = device_service.find_devices_by_type("light")
   # Прямой поиск через индекс

4. Поиск устройства по HA entity ID:
   device = device_service.find_device_by_ha_entity_id("light.kitchen")
   # Использует индекс для уникального поиска

5. Получение статистики:
   cache_stats = device_service.get_cache_stats()
   index_stats = device_service.get_index_stats()
   print(f"Cache hits: {cache_stats['cache_hits']}")
   print(f"Index operations: {index_stats['index_operations']}")

Ожидаемое улучшение производительности
======================================

- Cache hit rate: 60-80% для типичных рабочих нагрузок
- Время поиска устройства: O(1) при попадании в кэш
- Время поиска по источнику: O(1) индексированный поиск вместо O(n) полного сканирования
- Время поиска по типу: O(1) индексированный поиск вместо O(n) полного сканирования
- Общее улучшение производительности: 50%+ для типичных операций

Вытеснение и инвалидация
========================

DeviceCache использует LRU стратегию вытеснения:
- Когда кэш достигает максимального размера (1000 записей)
- Удаляется элемент, на который дольше всего не было доступа
- Все операции с кэшем логируются

TTL инвалидация:
- Каждый элемент имеет время жизни (по умолчанию 300 секунд)
- При попытке получить истекший элемент, он удаляется из кэша
- Метод cleanup_expired() очищает все истекшие записи

Явная инвалидация:
- invalidate(key) - удалить конкретный элемент
- invalidate_by_prefix(prefix) - удалить все элементы с префиксом
- clear() - очистить весь кэш
- При обновлении состояния устройства инвалидируются связанные кэши

Thread-Safety
=============

Обе составляющие используют RLock для безопасности потоков:
- DeviceCache использует threading.RLock для синхронизации
- IndexManager использует threading.RLock для синхронизации
- Все критические операции защищены блокировкой
- Deadlock-free благодаря использованию контекстного менеджера with

Мониторинг и отладка
====================

Логирование:
- Все операции с кэшем логируются на уровне DEBUG
- Инвалидации логируются на уровне INFO
- Ошибки логируются на уровне ERROR

Метрики:
- cache_hits - количество попаданий в кэш
- cache_misses - количество промахов кэша
- cache_invalidations - количество инвалидаций
- hit_rate_percent - процент попаданий в кэш
- index_operations - количество операций индексирования
- index_errors - количество ошибок индексирования

Рекомендации
============

1. Размер кэша: 1000 записей оптимален для большинства применений
   - Можно увеличить до 5000 если устройств много
   - Можно уменьшить до 100 если памяти мало

2. TTL кэша: 300 секунд - хороший компромисс
   - Можно уменьшить до 60 сек для более частого обновления
   - Можно увеличить до 900 сек для стабильной конфигурации

3. Периодическое обслуживание:
   - Вызывать cleanup_expired() каждые 5-10 минут
   - Мониторить cache_stats и index_stats в Prometheus

4. При добавлении/удалении устройств:
   - Вызывать rebuild_index() для полной синхронизации
   - Или использовать add_devices_to_cache_and_index() для частичного обновления

Тестирование
============

Набор unit тестов включает:
- Базовые операции кэша (set, get, invalidate, clear)
- LRU вытеснение при переполнении
- TTL инвалидация с истечением времени
- Продление TTL (extend_ttl)
- Инвалидация по префиксу
- Очистка истекших записей
- Статистика и метрики
- Thread-safety с параллельными потоками
- Операции индексирования по всем критериям
- Обновление и удаление устройств
- Поиск по комбинированным критериям
- Thread-safety индекса

Всего: 30+ unit тестов, минимум 20 как требовалось
