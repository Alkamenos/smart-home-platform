# Шаг 6: Интеграция персистентности FSM

## Проблема (из код-ревью)

При рестарте HA или reload PyScript все FSM сбрасываются в `initial="OFF"`. Это приводит к:
- Потере активных режимов (PARTY, NIGHTLIGHT и т.д.)
- Рассинхронизации между физическим состоянием устройств и логикой автоматов
- Ложным срабатываниям StateSync

## Решение

Интегрирован модуль `FSMPersistence` который:
1. **Сохраняет** состояние при каждом переходе FSM
2. **Восстанавливает** состояние при старте платформы
3. **Валидирует** сохранённые состояния против текущих определений FSM

## Что сделано

### 1. Обновлён `loader.py`

Добавлена инициализация `FSMPersistence` в скрипте инициализации:

```python
from core.fsm_persistence import FSMPersistence

# Инициализируем персистентность состояний
persistence = FSMPersistence(event_bus, fsm_engine, ha_adapter, logger)

# Включаем персистентность для каждого автомата
for definition in lighting_defs + climate_defs:
    fsm_engine.register(definition)
    persistence.enable_for_entity(definition.entity_id)
```

### 2. Улучшен `fsm_persistence.py`

Исправлен метод `_restore_state`:
- Прямая установка состояния вместо триггера (который может не существовать)
- Добавление записи в историю переходов
- Публикация события `fsm.restored`
- Валидация состояния перед восстановлением

### 3. Создан тест `tests/test_fsm_persistence.py`

4 теста покрывают основные сценарии:
1. ✅ Сохранение при переходе
2. ✅ Восстановление при старте
3. ✅ Несколько автоматов
4. ✅ Отклонение невалидных состояний

## Как работает

### Сохранение (при переходе FSM)

```
FSM Transition → EventBus "fsm.transition" 
              → FSMPersistence._on_fsm_transition()
              → Сохранение в input_text.{key} или JSON файл
```

### Восстановление (при старте платформы)

```
Platform Started → EventBus "platform.started"
                → FSMPersistence._on_platform_started()
                → Чтение из хранилища
                → Валидация против определения FSM
                → Прямая установка состояния
                → Запись в историю "restore"
```

## Хранение данных

### Приоритет 1: input_text entities (в HA)
```yaml
input_text.light_living_room_mode:
  value: "PARTY"
```

### Приоритет 2: JSON файл (fallback)
```
~/.homeassistant/.storage/fsm_persistence/light_living_room_mode.json
{"state": "PARTY", "updated_at": 1788834144.89}
```

## Сервисы для отладки

Добавлен сервис `fsm_persist_list`:
```yaml
service: pyscript.fsm_persist_list
data: {}
```

Возвращает список автоматов с включенной персистентностью.

## Миграция

Для существующих установок:
1. Запустить `loader.py` для деплоя обновлённого `platform_v3_init.py`
2. Перезагрузить PyScript через `pyscript.reload`
3. Персистентность включится автоматически для всех автоматов
