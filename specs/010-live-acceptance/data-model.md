# Модель данных: Живой запуск

Сущности спецификации в терминах предметной области. Имена полей — проектные и
обязательные к соблюдению при реализации; формат хранения определяется
`plan.md`.

## Ручное действие

**Что это**: факт «устройством управлял человек», а не автоматика.

| Поле | Смысл | Правило |
|------|-------|---------|
| `device_id` | Устройство, которым управляли | обязательное; идентификатор сущности Home Assistant |
| `occurred_at` | Когда произошло | обязательное; настенное время |
| `origin` | Откуда действие | `ha_app` (событие с указанием пользователя), `physical` (выключатель, дошедший до HA — различается тем же признаком), `web_ui` (команда из интерфейса платформы) |
| `command` | Что сделали | необязательное; для веб-интерфейса — имя команды |
| `platform_restarted_since` | Не хранится | — |

**Правила**
- Одно устройство — одна последняя запись. История не нужна: блокировка
  определяется последним действием, а журнал переходов уже хранит историю
  отдельно.
- Действие без указания человека ручным **не** является. Это правило
  обязательно: иначе блокировку запускали бы автоматические сценарии сами у
  себя и система заблокировала бы себя.
- Действие по устройству без автоматики всё равно сохраняется: блокировка
  пригодится, когда автоматика появится.

## Блокировка

**Что это**: производное от ручного действия ограничение — автоматические
команды по устройству отклоняются до истечения срока.

| Поле | Смысл | Правило |
|------|-------|---------|
| `device_id` | Заблокированное устройство | обязательное |
| `until` | До какого момента действует | обязательное; настенное время |
| `lockout_minutes` | Длительность | из манифеста по типу устройства; не из кода |
| `cause` | Что вызвало | `manual_control` |

**Правила**
- Блокировка **не** хранится отдельной записью: она вычисляется из последнего
  ручного действия. Два источника правды означали бы расхождение.
- Истечение определяется сравнением времени, а не числом событий: устройство,
  которым не пользуются, должно перестать быть заблокированным само.
- Переживает перезапуск платформы (решение R-03): иначе перезапуск в момент,
  когда жилец пробует выключить свет, отменял бы блокировку в первую же минуту.
- Повторное ручное действие продлевает отсчёт от него, а не от первого.

## Показание датчика

**Что это**: измеримое значение, по которому условие перехода выносит решение.

| Поле | Смысл | Правила |
|------|-------|---------|
| `role` | Роль датчика | `humidity`, `temperature`; совпадает с ключом, который читает условие |
| `value` | Значение | число, если значение приводится к числу; иначе исходная строка |
| `entity_id` | Сущность-источник | обязательное; совпадает с датчиком в манифесте |

**Правила**
- Значение кладётся в контекст перехода под именем роли, а не под общим именем:
  иначе условие перестаёт знать, чей это датчик, и при двух датчиках в комнате
  решение становится неоднозначным.
- Нечисловое значение («unavailable», пустая строка) **не** превращается в
  ноль. Ноль — это число, и молчаливое сравнение выдало бы «влажность 0, значит
  выключить» за честное решение.
- Значение приходит от датчика, чья сущность совпадает с датчиком в манифесте.
  Значение чужой сущности в решение не попадает.

## Требование условия к данным

**Что это**: объявление, какие данные нужны условию, чтобы его отказ можно было
прочитать.

| Поле | Смысл | Правило |
|------|-------|---------|
| `guard` | Имя условия | обязательное |
| `requires` | Какие данные нужны | список ключей контекста; пустой список означает «данные не нужны» |

**Правила**
- Проверяется **до** вызова условия. Нет данных — отказ с причиной «данных
  нет», условие не вызывается вовсе.
- Это не меняет контракт условий: они остаются функциями «да/нет».
- Условие без объявления считается не требующим данных: обратная совместимость,
  условие, добавленное позже, не сломает переходы неожиданным отказом.

## Отказ перехода

**Что это**: запись о невыполненном переходе с причиной, понятной оператору.

| Поле | Смысл | Правила |
|------|-------|---------|
| `reason` | Причина | различимы: неизвестная сущность, нет состояния, сглаживание, нет подходящего перехода, отказ условия, **нет данных для условия** |
| `device_id` | Устройство | обязательное |
| `remaining_lockout_sec` | Остаток блокировки | заполняется при отказе по блокировке; иначе отсутствует |

**Правила**
- Причины различимы и наблюдаемы. Сейчас «влажность ниже порога» и «влажности
  не было» дают один и тот же отказ — из-за этого владелец не может понять,
  почему вентиляция молчит.
- Отказ по блокировке несёт остаток срока: оператор должен видеть, что
  автоматика выключена намеренно, а не сломалась.

## Шаг приёмки

**Что это**: одна проверяемая операция из процедуры запуска.

| Поле | Смысл | Правила |
|------|-------|---------|
| `order` | Порядковый номер | обязательное; порядок не меняется без причины |
| `action` | Что делает владелец | обязательное; формулировка без обращения к коду |
| `success_signal` | Признак успеха | обязательное; наблюдаем без специальных инструментов |
| `stop_condition` | Когда остановиться | обязательное; при срабатывании процедура прекращается |
| `result` | Фактический результат | `passed`, `failed`, **`not_checked`** |

**Правила**
- `not_checked` — допустимый и обязательно записываемый результат. Отсутствие
  записи не считается ничем: несколько дефектов числились закрытыми без единой
  живой проверки, и следом оставалась только строка в Known Issues.
- Шаг считается пройденным только при выполненном `success_signal`. «Вроде
  работает» результатом не является.

## Связи

```
Ручное действие ──вычисляется──> Блокировка ──ограничивает──> Команда
       │                                                      │
       └── источник данных для ──> Отказ по блокировке <──────┘
                                    (в журнале переходов и показателях)

Показание датчика ──попадает в контекст перехода──> Требование условия
       │                                                      │
       └── при отсутствии ──> Отказ «нет данных» <────────────┘
```

Одна связь требует внимания: **блокировка вычисляется, а не хранится**. Хранить
и ручное действие, и блокировку — значит завести два источника правды, которые
разойдутся при первом же расхождении времён.
