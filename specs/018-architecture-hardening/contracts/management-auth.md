# Contract: граница управления

**Feature**: `018-architecture-hardening` | **Version**: 1.0 | **Date**: 2026-11-02

## Назначение

Определить, кто и при каких условиях может менять дом, и что происходит при
отказе. Контракт применяется ко всем интерфейсам: Web UI, HTTP API, CLI,
Home Assistant ingress.

## Источники идентичности

| Источник | Когда доверяется | Как проверяется |
|---|---|---|
| Home Assistant ingress | запрос пришёл из доверенного прокси-диапазона | заголовки ingress + сетевой источник |
| Сессия владельца | вход по паролю владельца | подписанная HttpOnly-cookie, `SameSite=Strict` |
| Bearer-токен | API и CLI | токен из окружения, сравнение постоянного времени |
| Аноним | только allowlist состояния | отсутствие идентичности |

**Запрещено**: выводить права из `X-Is-Admin`, `X-User-ID` или любого другого
заголовка, присланного клиентом напрямую.

## Роли

| Роль | Может |
|---|---|
| owner | всё: описание, команды, доступы, публикация |
| guest | просмотр; команды по выданному доступу |
| automation | команды в рамках поведения |
| monitor | `/health`, `/ready`, `/metrics` |

## Allowlist без идентичности

- `GET /health`
- `GET /ready`
- `GET /metrics`
- статические файлы интерфейса
- вход в сессию (`POST /api/v1/session/login`)

Всё остальное — default deny.

## Матрица (обязательная)

| Операция | Аноним | monitor | guest | owner | ingress-owner |
|---|---|---|---|---|---|
| Чтение состояния дома | deny | deny | allow | allow | allow |
| Изменение описания | deny | deny | deny | allow | allow |
| Команда прибору | deny | deny | по доступу | allow | allow |
| Публикация панели | deny | deny | deny | allow | allow |
| Выдача доступа | deny | deny | deny | allow | allow |
| `/health`, `/ready`, `/metrics` | allow | allow | allow | allow | allow |

## Ответы

| Ситуация | Код | Тело |
|---|---|---|
| Нет идентичности | 401 | `{"error": {"code": "unauthenticated", ...}}` |
| Идентичность есть, прав нет | 403 | `{"error": {"code": "forbidden", ...}}` |
| Подделанный признак прав | 403 | как `forbidden`, без раскрытия деталей |
| Доверенный прокси не подтверждён | 401 | как `unauthenticated` |

Каждый отказ пишется в журнал: источник, операция, причина, `trace_id`.
Секреты и внутренние пути в ответ не попадают.

## CSRF

Для cookie-сессии изменяющие запросы требуют:

- `SameSite=Strict` (или `Lax` с проверкой `Origin`);
- совпадение `Origin`/`Referer` с доверенным;
- отсутствие кросс-доменных CORS-разрешений.

Bearer-токен CSRF не подвержен.

## Запрещено

- Защищать маршруты по одному и забывать новые: middleware глобальный.
- Считать `localhost` достаточной защитой.
- Возвращать 200 на отклонённую операцию.
- Логировать токены, cookie и пароли.
