# Contract: правила зависимостей и границ

**Feature**: `018-architecture-hardening` | **Version**: 1.0 | **Date**: 2026-11-02

## Назначение

Сделать архитектурные границы исполняемыми: нарушение должно ломать проверку, а
не обсуждаться на ревью.

## Разрешённые направления

```text
app / webui / cli
        │
        ▼
   services (прикладные)
        │
        ▼
      core (домен и рантайм)
        ▲
        │
   adapters (реализуют порты)
```

| Из | Куда можно | Куда нельзя |
|---|---|---|
| `core` | `core` | `adapters`, `webui`, `services`, `dashboard` |
| `adapters` | `core` (порты/модели) | `webui`, `services` |
| `services` | `core`, `adapters` (через порт) | `webui` |
| `webui` | `core`, `services` | `adapters` напрямую (кроме разрешённых портов) |
| `dashboard` | `core` | `webui`, `services` |
| `app` | всё | — (composition root) |

Исключения оформляются явно в allowlist с причиной и сроком; «исторически так
сложилось» — не причина.

## Обязательные проверки

| Проверка | Ожидание |
|---|---|
| `core` не импортирует инфраструктуру | 0 нарушений |
| Доменная модель одна | 0 параллельных определений |
| Новый файл ≤ 800 строк | отказ при превышении |
| Существующие крупные файлы | allowlist с целью сокращения ≥ 50 % |
| Публичный контракт при разделении | не меняется без решения |

## Что считается нарушением

- Импорт конкретного адаптера в домене.
- Вторая Pydantic-модель того же доменного понятия.
- Копия правил проверки в другом слое.
- «Утилитарный» модуль, который знает про всё сразу.
- Обход правила через динамический импорт или `importlib` без явного allowlist.

## Проверка в конвейере

- `tests/architecture/` — AST-проверки импортов, размера, параллельных моделей.
- Проверка запускается в общем прогоне и в CI.
- Нарушение — красный тест, а не предупреждение.

## Запрещено

- Ослаблять проверку ради зелёного прогона.
- Добавлять исключение без причины и срока.
- Переносить код в `app`, чтобы формально обойти правило.
