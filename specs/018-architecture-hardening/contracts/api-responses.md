# Contract: ответы и ошибки внешних операций

**Feature**: `018-architecture-hardening` | **Version**: 1.0 | **Date**: 2026-11-02

## Назначение

Сделать поведение внешних операций предсказуемым: успешная форма сохраняется,
ошибка — единый конверт, у каждой ошибки есть код, сообщение и корреляция.

## Успешные ответы

- Существующие формы JSON **не меняются** без отдельного решения: клиенты и
  автоматизации уже на них завязаны.
- Для каждой операции объявляется DTO ответа (`response_model`), даже если
  физическая форма остаётся прежней.
- Списочные ответы сохраняют текущие поля; новые поля добавляются
  дополнительно, а не вместо.

## Ошибка: единый конверт

```json
{
  "error": {
    "code": "forbidden",
    "message": "Недостаточно прав для изменения описания дома",
    "fields": [],
    "trace_id": "a1b2c3d4"
  }
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `code` | да | машинный код, стабильный |
| `message` | да | человеческое объяснение |
| `fields` | нет | ошибки по полям формы |
| `trace_id` | да | связь с журналом |

## Коды

| Код | HTTP | Когда |
|---|---|---|
| `unauthenticated` | 401 | нет доверенной идентичности |
| `forbidden` | 403 | прав недостаточно |
| `not_found` | 404 | объекта нет |
| `validation_failed` | 400 | входные данные неверны |
| `manifest_invalid` | 400 | описание дома не прошло проверку |
| `manifest_shrink` | 409 | запись потеряла бы комнаты/приборы |
| `conflict` | 409 | состояние изменилось параллельно |
| `upstream_unavailable` | 502/503 | внешняя система не ответила |
| `internal_error` | 500 | дефект; без внутренних деталей |

## Правила

1. `trace_id` присутствует и в ответе, и в журнале.
2. Внутренние пути, трассировки и секреты в ответ не попадают.
3. Ожидаемый отказ (нет данных, прибор недоступен) не превращается в 500.
4. Ошибка внешней системы не маскируется под успех.
5. Ответы проходят валидацию DTO, а не собираются «сырым» словарём.

## Запрещено

- Возвращать `{"error": "текст"}` без кода.
- Отдавать HTML-страницу ошибки вместо JSON для API.
- Логировать тело запроса с токеном или паролем.
- Вводить разные форматы ошибок для разных маршрутов.

## Реализация

- `src/webui/errors.py` — обработчики `HTTPException`,
  `RequestValidationError`, `PlatformError` и неожиданных исключений.
- `trace_id` приходит из `RequestIdMiddleware` и возвращается в теле и
  заголовке `X-Trace-ID`.
- `src/core/errors.py` — категории отказов и их HTTP-статусы.
- DTO `response_model` объявлены для маршрутов устройств, манифеста, локаций и
  здоровья.
- JSON-формат структурных логов проверяется `tests/unit/core/test_structured_logging.py`.
- Контрактные проверки: `tests/contract/test_error_contract.py`,
  `tests/contract/test_trace_correlation.py`.
