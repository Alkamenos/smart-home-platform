# Data Model: Контроль доступа к устройствам (Access Control)

**Feature**: specs/004-device-access-control | **Date**: 2026-09-29

## Обзор

Домен доступа уже реализован в кодовой базе (модель, персистентность, сервис-методы). Фича — интеграция в web-каналы; модель расширяется только там, где это подтверждено acceptance-тестами (никаких изменений модели не планируется).

## DeviceAccess *(существует, не меняется)*

Запись доступа пользователя к устройству (`src/core/models/device_access.py`):

| Поле | Тип | Правила |
|---|---|---|
| `id` | UUID | авто (`uuid4`), уникален |
| `device_id` | UUID | ссылка на устройство; уникальность пары (device_id, user_id) на уровне сервиса |
| `user_id` | str | идентификатор пользователя из заголовка запроса |
| `role` | Literal["viewer", "controller", "admin"] | фиксированная иерархия; viewer=0 < controller=1 < admin=2 |
| `granted_by` | str | идентификатор администратора, выдавшего доступ |
| `created_at` | datetime | utcnow при создании |

**Анти-дубликат (уровень сервиса)**: повторный `grant_access` той же паре (device_id, user_id) обновляет роль существующей записи (не создаёт вторую).

## Связанные сущности *(существуют, не меняются)*

- **Device** (`src/core/models/device.py`): устройство платформы; доступ выдаётся на устройство. Видимость пользователю = наличие записи доступа.
- **DeviceResponse**: сериализация устройства в списках (существующие маршруты); состав не меняется.
- **SyncEvent / DeviceAccessChangedEvent**: запись в истории операций о каждом назначении/отзыве доступа (сервис публикует событие при изменениях).

## Сервисные методы *(существуют, не меняются)*

| Метод | Сигнатура | Семантика |
|---|---|---|
| `check_device_access` | `(device_id: UUID, user_id: str, required_role="viewer") -> bool` | роль пользователя на устройстве ≥ требуемой (иерархия viewer<controller<admin); False при любых проблемах |
| `grant_access` | `(device_id, user_id, role, granted_by) -> DeviceAccess \| None` | создание/обновление записи; None при невозможности (устройство не найдено и т.п.) |
| `revoke_access` | `(access_id: UUID) -> bool` | удаление записи; False при отсутствии |
| `get_device_accesses` | `(device_id) -> list[DeviceAccess]` | все записи устройства |
| `get_user_accessible_devices` | `(user_id: str) -> list[Device]` | устройства с выданными доступами (admin → все) |

## Персистентность *(существует, не меняется)*

`DeviceAccessPersistence` (`src/core/persistence/devices.py:271`): JSON-файл в data-dir домена устройств; доступы переживают перезапуск платформы (FR-010). Загрузка по паре (device, user): `load_access_for_user_device`; по устройству: `load_accesses_for_device`.

## Новые ассоциации (web-слой)

### ConnectionIdentity (WS, новая структура web-слоя)

Ассоциация соединения с идентификацией для проверки прав при доставке (R5 research):

| Поле | Тип | Правила |
|---|---|---|
| `websocket` | WebSocket | ключ карты менеджера |
| `user_id` | str \| None | устанавливается при аутентификации/auth-сообщении; None → неаутентифицирован |
| `accessible` | set[str] (device_id str) | вычисляется при проверке при подписке/доставке; наполняется при прохождении проверки |

**Правило жизни**:

```
(соединение) --auth/подписка--> user_id известен
             --подписка с доступом--> устройство в accessible
             --событие устройства--> проверка при каждой доставке → отправка / пропуск
             --disconnect--> запись удалена
```

### Идентификация HTTP-запроса (request.state)

Middleware кладёт в `request.state`: `user_id` (из `X-User-ID`), `is_admin` (из `X-Is-Admin`), `device_id` (извлечённый из пути). Существующая семантика.

## Иерархия ролей (справка, существует)

| Роль | Уровень | Разрешения |
|---|---|---|
| viewer | 0 | чтение: детали, события (WS-подписка), список доступных устройств |
| controller | 1 | viewer + выполнение команд |
| admin | 2 | controller + настройка устройства, назначение/отзыв/список доступов, sources/sync |

Глобальный администратор (заголовок `X-Is-Admin=true`) имеет доступ ко всем endpoints устройств; персональные записи доступа ему не требуются.
