# Quickstart: состояние локации

**Feature**: 016-location-state · **Дата**: 2026-10-13

Как проверить, что наблюдение за локациями работает: снимок, журнал, зеркало.

## 1. Список локаций

```bash
curl -s http://localhost:8000/api/v1/locations | python3 -m json.tool
```

Ожидается: комнаты манифеста (`kind: room`) и особые зоны (`ulitsa`, `gryadki`)
с числом датчиков каждой.

## 2. Снимок локации

```bash
curl -s http://localhost:8000/api/v1/locations/ulitsa/state | python3 -m json.tool
```

Что смотреть:

| Поле | Что означает |
|------|--------------|
| `readings.<роль>[].value` / `unit` / `at` | значение, единица измерения HA и время последнего показания |
| `readings.<роль>[].stale` | датчик молчит дольше порога локации (у улицы и грядок — сутки, у комнат — час) |
| `readings.<роль>[].available` | состояние доступно (не `unavailable`/`unknown`) |
| `derived.occupied` | было движение не старее окна присутствия (10 минут) |
| `derived.last_motion_ago_sec` | сколько секунд с последнего срабатывания движения |
| `derived.contacts_open` | открытые окна и двери поимённо |
| `derived.stale_sensors` | какие датчики молчат |
| `derived.available_count` / `sensor_count` | сколько датчиков отвечает из привязанных |

Проверка «молчит ≠ не менялось»: подержите датчик без показаний дольше порога —
он останется в `readings` со старым значением, но попадёт в `stale_sensors`.
Недоступный датчик (`unavailable`) не идёт в производные: присутствие по мёртвому
датчику движения не считается.

## 3. Журнал изменений

```bash
# за сутки
curl -s "http://localhost:8000/api/v1/locations/spalnia/history" | python3 -m json.tool
# за интервал (принимается ISO 8601 и секунды epoch)
curl -s "http://localhost:8000/api/v1/locations/spalnia/history?from=2026-10-13T00:00:00&to=2026-10-13T23:59:59" \
  | python3 -m json.tool
```

Запись содержит `at`, `entity_id`, `role`, `old_value`, `value`. Повтор того же
значения в журнал не пишется: это журнал изменений, а не поток «каждую минуту».
Срок хранения — общий с журналом событий (30 дней).

## 4. Зеркало в Home Assistant (после фазы 5)

Платформа публикует конфигурацию автообнаружения и значения в MQTT (`retain`),
сущности создаёт сам Home Assistant:

- `sensor.behavioral_<локация>_<роль>` — по каждому показателю (для графиков);
- `sensor.behavioral_<локация>` — сводная сущность локации, полный снимок в
  атрибутах (`json_attributes_topic`) — её читает анализ.

Проверка: в Home Assistant → Developer Tools → States найти
`sensor.behavioral_ulitsa` и убедиться, что в атрибутах лежит тот же снимок, что
отдаёт HTTP. Перезапустите HA: сущности восстанавливаются без ожидания события
(публикация с `retain`).

Идентификаторы предсказуемы: `<роль>` даёт `sensor.behavioral_ulitsa_temperature`,
`binary_sensor.behavioral_ulitsa_rain` (движение, контакт и дождь — бинарные
датчики), сводная сущность — `sensor.behavioral_ulitsa`. В интерфейсе они лежат
под устройством «Улица» и названы по-русски («температура», «дождь»).

Отказ MQTT не ломает снимок и журнал: он виден в журнале платформы, а состояние
продолжает обновляться.
