# Модель данных: Климат

## Сущности

### Комната климата

Описывается в манифесте как комната с датчиком температуры и одним или несколькими
обогревателями.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `sensors.temperature` | `entity_id` | да | Датчик температуры комнаты (`sensor.*`) |
| `devices[].id` | `entity_id` | да | Обогреватель комнаты (`switch.*`) |
| `devices[].behaviors[].template` | `climate_control` | да | Поведение климата |
| `devices[].behaviors[].params.hysteresis` | число | нет | Ширина «мёртвой зоны» вокруг цели, °C. По умолчанию 0.5 |
| `devices[].behaviors[].params.run_minutes` | число | нет | На сколько минут включается обогреватель через его таймер. По умолчанию 15 |
| `devices[].behaviors[].params.heater_timer` | `entity_id` | нет | Таймер обогревателя (`number.*_countdown`). Нет — работа по датчику с записью в журнал |
| `devices[].behaviors[].params.managed_by_hardware` | булево | нет | В комнате стоит термостат; платформа обогревателем не управляет |

**Правила проверки**:
- `hysteresis` ≥ 0 и ≤ 2 °C: шире — промах мимо комфорта, уже — дрожание.
- `run_minutes` > 0: нулевой интервал означает «включить и забыть», а это ровно
  тот перегрев, которого фича избегает.
- `heater_timer` должен принадлежать домену `number`, иначе команда `number.set_value`
  не имеет смысла и вернёт ошибку Home Assistant.

### Правила дома (automation_rules.climate)

Все идентификаторы глобальных правил — в манифесте, в коде значений нет
(конституция V).

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `setpoint_entity` | `entity_id` | да | Целевая температура дома (`input_number.*`), FR-001 |
| `comfort_max_entity` | `entity_id` | да | Потолок комфорта (`input_number.*`), FR-008 |
| `season_entity` | `entity_id` | да | Флаг «зима» (`input_boolean.*`), FR-011 |
| `ac_entity` | `entity_id` | нет | Кондиционер (`climate.*`), FR-009 |
| `ac_allowed_entity` | `entity_id` | нет | Разрешение кондиционера владельцем (`input_boolean.*`), FR-009 |
| `feature_flag_entity` | `entity_id` | нет | Фиче-флаг климата (`input_boolean.*`), FR-013 |
| `shadow_mode_entity` | `entity_id` | нет | Режим тени (`input_boolean.*`), FR-013 |
| `thermostat_entity` | `entity_id` | нет | Термостат гостиной, для сверки уставки, FR-014 |
| `thermostat_divergence` | число | нет | Допустимое расхождение уставок, °C. По умолчанию 1.0 |
| `night_max_fan_percent` | число | нет | Резерв для спецификации вентиляции; здесь не используется |

**Правила проверки**: все `entity_id` обязаны быть уникальны внутри блока;
`thermostat_divergence` ≥ 0.

## Контекст решения

Ключи, которые условия читают из контекста перехода. Источник — адаптер
(для глобальных правил) и роутер (для датчика комнаты).

| Ключ | Тип | Источник | Смысл |
|------|-----|----------|-------|
| `temperature` | число или строка | роутер, роль датчика (`event_router.py:205-207`) | Показание датчика комнаты; `unavailable` остаётся строкой |
| `climate_setpoint` | число или None | адаптер, `input_number` | Целевая температура дома |
| `comfort_max` | число или None | адаптер, `input_number` | Потолок комфорта |
| `is_winter` | булево или None | адаптер, `input_boolean` | Сезон: зима или лето |
| `ac_allowed` | булево или None | адаптер, `input_boolean` | Разрешение кондиционера владельцем |
| `climate_enabled` | булево или None | адаптер, `input_boolean` | Фиче-флаг климата |
| `climate_shadow` | булево или None | адаптер, `input_boolean` | Режим тени |
| `daylight` | булево или None | адаптер, солнце | Для отладки: климат от солнца не зависит |
| `sleep_modifier_on` | булево или None | адаптер, модификатор | Для отладки: климат от «мы спим» не зависит |

**Правило**: значение `None` означает «состояние неизвестно» и приводит к
отказу с причиной `guard_data_missing` — а не к решению по умолчанию. Это
согласуется с принципом модуля условий (отказ при нехватке данных) и с FR-016.

## Состояния автомата

```text
        температура < цель − гистерезис
IDLE ──────────────────────────────────► HEATING
  ▲                                      │
  │  температура ≥ цель                  │ таймер истёк (timeout)
  └──────────────────────────────────────┘
```

| Состояние | Смысл | Как выходит |
|-----------|-------|-------------|
| `IDLE` | Огреваться незачем | Событие `temperature_changed` |
| `HEATING` | Обогреватель работает по своему таймеру | Истечение `timeout_sec` (равно `run_minutes`) либо достижение цели |

**Переходы и условия**:

| Из | В | Событие | Условия | Действие |
|----|----|---------|---------|----------|
| IDLE | HEATING | `temperature_changed` | `below_setpoint` | `heater_timer_on` (или `switch_on` без таймера) |
| IDLE | IDLE | `temperature_changed` | — | `null` (решение «не греть» не требует команды) |
| HEATING | IDLE | `timeout` | — | `heater_off` |
| HEATING | IDLE | `temperature_changed` | `at_or_above_setpoint` | `heater_off` |

**Почему `IDLE → IDLE` существует**: без него каждое событие датчика при
нормальной температуре превращалось бы в отказ «нет такого перехода» — тот самый
шум, из-за которого ночной цикл суток молчал (дефект, вскрытый 2026-10-09).
Переход в то же состояние без действия означает «решение принято, исполнять
нечего».

## Причины отказов

Расширение словаря `GUARD_DENIAL_REASONS` (`src/core/events/fsm_events.py`):

| Причина | Когда |
|---------|-------|
| `setpoint_unavailable` | Целевая температура не прочитана или вне диапазона (FR-018) |
| `climate_disabled` | `feature_climate` = off (FR-013) |
| `ac_not_allowed` | Владелец не разрешил кондиционер (FR-009) |
| `ac_forbidden_in_winter` | Попытка охлаждения зимой (FR-011) |
| `managed_by_hardware` | В комнате термостат, платформа не управляет (FR-007) |
| `guard_data_missing` | Нет данных датчика комнаты или уставки (FR-016) |

Каждая причина обязана быть различима утром по журналу: «спим», «ночь»,
«светло», «нет данных» и «выключено владельцем» — это пять разных ситуаций,
и склейка их в `guard_failed` запрещена правилом владельца о логах.

## Связи

```text
Правила дома (automation_rules.climate)
   │  уставка, потолок, сезон, флаги
   ▼
Контекст события ──────────► Условия (guards/builtin.py)
   │  temperature                │
   ▼                             ▼
Комната климата ──────────► Автомат (FSM) ──► Действие ──► CommandIntent
   │  датчик, обогреватель                    (number.set_value
   │                                          или switch.turn_on/off)
   └──► термостат (справочно, FR-014)
```
