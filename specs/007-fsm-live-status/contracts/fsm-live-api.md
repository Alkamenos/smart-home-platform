# Contract: REST и WebSocket интерфейса состояний

**Feature**: specs/007-fsm-live-status | **Дата**: 2026-10-01

Область контракта: чтение состояний автоматов через REST и доставка живых обновлений через WebSocket, а также изменения в разделах визуализаций. Транспорт: HTTP/1.1 + JSON; идентификация — заголовки `X-User-ID` и `X-Is-Admin` (существующий механизм, specs/004).

---

## Идентификация

| Заголовок | Обязательность | Значение |
|---|---|---|
| `X-User-ID` | обязателен для разделов с правами | идентификатор пользователя |
| `X-Is-Admin` | необязателен | `true` — права администратора |

Поведение доступа **не меняется**: `GET /api/v1/devices` остаётся открытым для чтения списка (сама фильтрация по правам — в ответе), остальные разделы требуют заголовок.

## 1. Состояния всех автоматов

`GET /api/fsm/state`

```json
{
  "count": 3,
  "states": [
    {
      "fsm_id": "light.kitchen_lighting_10",
      "device_id": "light.kitchen",
      "behavior": "lighting",
      "state": "ON_MOTION",
      "since": "2026-10-01T14:23:11.482913",
      "automated": true
    }
  ]
}
```

| Ситуация | Ответ |
|---|---|
| есть автоматы | `200`, `states` — массив, `count` — его длина |
| автоматов нет | `200`, `{"count": 0, "states": []}` — **не** ошибка |
| сервис состояний недоступен | `503`, `{"error": "<причина>"}` — не пустой список (FR-020) |

**Соглашения**:
- соответствует состоянию движка на момент запроса, без устаревающего кэша (FR-018);
- `since` — настенное время последнего перехода; `null`, если переходов не было;
- формат времени единый с разделом событий и живыми сообщениями (FR-023).

**Разграничение доступа** (FR-038): ответ содержит только автоматы устройств, доступных пользователю. У пользователя без доступных устройств — `{"count": 0, "states": []}`.

## 2. Список устройств — состояние автоматики

`GET /api/v1/devices` — расширение существующего ответа. Существующие поля сохраняются без изменений; добавляются:

```json
{
  "id": "3f7bcdb0-3dfd-4940-b10e-8625a8772e1d",
  "name": "Кухонный свет",
  "state": { "state": "on" },
  "fsm": [
    { "fsm_id": "light.kitchen_lighting_10", "device_id": "light.kitchen",
      "behavior": "lighting", "state": "ON_MOTION",
      "since": "2026-10-01T14:23:11.482913", "automated": true }
  ],
  "automation": { "configured": true, "fsm_ids": ["light.kitchen_lighting_10"] }
}
```

Устройство **без** автоматики (FR-019):

```json
{
  "fsm": [],
  "automation": { "configured": false, "fsm_ids": [], "reason": "no_automation" }
}
```

**Форма `automation` единая**: ключи `configured`, `fsm_ids`, `reason` присутствуют всегда, чтобы клиенту не приходилось разбирать разные формы.

**Правило различения**: `fsm: []` означает «автоматика не настроена», а не «сервис недоступен». Недоступность сигнализуется кодом 503 с описанием (FR-020).

**Обратная совместимость**: добавление полей не ломает существующих потребителей; контрактные тесты устройств (`tests/contract/test_devices_api.py`) проверяют прежние поля и должны остаться зелёными без правок.

## 3. Диаграмма состояний

`GET /api/fsm/{entity_id}/diagram`

**Изменение формата** (FR-029): вместо конверта `{"diagram": "..."}` с `application/json` отдаётся чистая Mermaid-строка с `text/plain`.

```
stateDiagram-v2
    [*] --> OFF
    OFF --> ON_MOTION : motion_detected
    ON_MOTION --> OFF : timeout
```

| Поле/ситуация | Значение |
|---|---|
| успех | `200`, `text/plain`, тело — Mermaid-строка |
| автомат не найден | `404`, JSON с описанием (сохраняется как есть) |
| платформа недоступна | `503`, JSON с описанием |

**Почему**: JSON-конверт с последующей вставкой в страницу как текста — источник дефекта `dashboard.html`. `index.html` уже работает правильно через распаковку.

**Текущее состояние в диаграмму не входит** — оно приходит из разделов 1–2 и по WebSocket; подсветка выполняется на клиенте (FR-030). Это осознанное изменение: перерисовка схемы при каждом переходе означала бы передачу текста схемы по сети на каждое событие.

## 4. Живые обновления (WebSocket)

Базовый канал — **существующий** `GET /api/v1/ws/devices` (он уже умеет идентификацию, подписки и проверку прав). Эндпоинт `/ws/live` выводится из эксплуатации: в нём нет ни идентичности, ни проверки прав, а требования FR-025/FR-039 их требуют.

### Рукопожатие и подписка (без изменений)

Клиент → сервер:

```json
{"type": "auth", "user_id": "51f29a8f-1d2e-4b3a-9c8d-7e6f5a4b3c2d"}
{"type": "subscribe", "device_id": "3f7bcdb0-3dfd-4940-b10e-8625a8772e1d"}
```

Сервер → клиент: `{"type": "authenticated", ...}`, `{"type": "subscribed", ...}` — формы сохраняются.

### Сообщение о переходе (новое)

```json
{
  "type": "fsm_transition",
  "device_id": "3f7bcdb0-3dfd-4940-b10e-8625a8772e1d",
  "fsm_id": "light.kitchen_lighting_10",
  "from_state": "OFF",
  "state": "ON_MOTION",
  "source": "automatic",
  "timestamp": "2026-10-01T14:23:11.482913"
}
```

| Поле | Тип | Примечание |
|---|---|---|
| `type` | строка | `fsm_transition` — значение, которое клиент уже ожидает (`index.html:849`) |
| `device_id` | строка (UUID) | устройство для маршрутизации и проверки прав |
| `fsm_id` | строка | какой автомат перешёл |
| `from_state` | строка \| null | прежнее состояние |
| `state` | строка | новое состояние |
| `source` | `manual` \| `automatic` | источник перехода |
| `timestamp` | строка (ISO-8601) | время перехода |

### Гарантии доставки

| Правило | Требование |
|---|---|
| Кому | только соединениям, подписанным на это устройство **и** прошедшим проверку доступа в момент отправки (FR-025) |
| Скорость | доставка ≤2 с после перехода (SC-003) |
| Порядок | не гарантируется; при потоке событий клиент обязан показывать актуальное состояние, а не накапливать устаревшие сообщения (FR-031) |
| Анонимная подписка | невозможна: без `auth` подписка отклоняется (FR-039) |
| Разрыв | клиент переподключается с нарастающей паузой; после переподключения получает актуальные состояния запросом раздела 1 (FR-026, FR-028) |
| Признак недоступности | интерфейс показывает его самому себе в течение 10 с после обрыва (FR-027, SC-008) |

**Обратная совместимость**: существующий раздатчик `broadcast_state_change` и его вызов из `tests/integration/test_access_control.py` сохраняются.

## 5. Разделы визуализаций — честные данные

### 5.1 Карта активности

`GET /api/history/activity-heatmap`

```json
{
  "days": ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"],
  "hours": [0, 1, "…", 23],
  "data": [
    {"day": "Mon", "values": [0, 0, 1, 0, 2, 5, 11, 14, 9, 4, 2, 3, 6, 8, 5, 3, 4, 9, 17, 21, 14, 8, 3, 1]}
  ],
  "has_data": true
}
```

При отсутствии записей: `"data": []`, `"has_data": false` (FR-032, FR-036).

**Что изменилось**: `days`, `hours`, `data` сохраняют форму, а значения перестают быть выдуманными — считаются по таблице переходов и таблице событий. Ключ `has_data` добавлен.

### 5.2 История событий

`GET /api/events/history`

```json
{
  "labels": ["00:00", "01:00", "…", "23:00"],
  "datasets": [{ "label": "Events (Last 24h)", "data": [0, 0, 1, "…"], "borderColor": "#0d6efd" }],
  "has_data": true
}
```

**Два изменения** (FR-033, краевой случай спеки):
1. данные настоящие — из таблицы событий, писатель появляется вместе с публикацией переходов;
2. **ось времени исправлена**: корзины считались «часов назад» при подписях, идущих от `00:00`, из-за чего график отображался задом наперёд.

### 5.3 Подсказки

`GET /api/ai/suggestions`

```json
{ "suggestions": [], "has_data": false }
```

**Что изменилось**: три выдуманные записи удалены полностью (решение D-2). Форма ответа меняется с массива на объект — это изменение, ломающее текущего потребителя, поэтому оно выполняется вместе с правкой `dashboard.html` в одной задаче (решение D-2 фиксирует, что правдоподобная ложь недопустима; пустой раздел — единственная честная альтернатива).

### 5.4 Оверрайды (без изменений)

`GET /api/overrides` — единственный раздел с настоящими данными сегодня, сохраняется как есть.

| Объект | Причина |
|---|---|
| эндпоинт `/ws/live` и его менеджер подключений (`app.py:423-470`) | нет идентичности и проверки прав; выводится в пользу канала устройств (R-08) |

| вторая шина событий в веб-слое (`app.py:357`) | FR-006: одна шина на процесс |

## 7. Что не меняется

| Объект | Причина |
|---|---|
| `POST /api/v1/devices/apply`, команды, конфигурация, доступ | вне объёма |
| формат ответа устройства (прежние поля) | обратная совместимость |
| протокол `auth`/`subscribe`/`unsubscribe`/`ping` | уже работает и покрыт тестами |
| схема манифеста | конституция V — миграции не требуются, потому что схема не меняется |
