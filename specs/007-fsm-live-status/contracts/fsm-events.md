# Contract: события перехода автомата

**Feature**: specs/007-fsm-live-status | **Дата**: 2026-10-01

Контракт внутреннего интерфейса: форма событий, которые движок состояний публикует в шину, и правила их доставки. Транспорт — шина событий платформы; потребители — хранилище состояний, журнал переходов, веб-мост, зеркало в Home Assistant, метрики (вне объёма).

Событие публикуется **настенным** временем в формате ISO-8601 — тем же, что уже используют события `device.*`.

---

## Имена событий

| Имя | Когда | Направление |
|---|---|---|
| `fsm.transitioned` | переход автомата **выполнен** | движок → подписчики |
| `fsm.rejected` | переход **отклонён** (с причиной) | движок → подписчики |
| `fsm.restored` | состояние автомата восстановлено при старте | хранилище → подписчики |
| `platform.started` | платформа завершила инициализацию | контейнер → подписчики |

Имя `fsm.transition` из существующего кода (`core/fsm/persistence.py:57`) **не используется**: оно не различает успех и отказ, а FR-004 требует различения. Существующий подписчик переводится на `fsm.transitioned`. Имя `fsm.state.changed` (`src/dashboard/dashboard.py:41`) также не используется — единый источник событий перехода один.

## Форма `fsm.transitioned`

```json
{
  "fsm_id": "light.kitchen_lighting_10",
  "device_id": "light.kitchen",
  "behavior": "lighting",
  "from_state": "OFF",
  "to_state": "ON_MOTION",
  "event": "motion_detected",
  "source": "automatic",
  "timestamp": "2026-10-01T14:23:11.482913",
  "outcome": "transitioned",
  "trace_id": "a1b2c3d4"
}
```

| Поле | Тип | Обязательность | Примечание |
|---|---|---|---|
| `fsm_id` | строка | да | схема `{устройство}_{шаблон}_{приоритет}` |
| `device_id` | строка | да | фактическое устройство (`target_device_id`) |
| `behavior` | строка | да | имя шаблона поведения |
| `from_state` | строка \| null | да | `null` при первом входе в состояние |
| `to_state` | строка | да | новое состояние |
| `event` | строка | да | событие-триггер |
| `source` | `manual` \| `automatic` | да | по префиксу `manual_` (R-03) |
| `timestamp` | строка | да | ISO-8601, настенное время |
| `outcome` | строка | да | всегда `"transitioned"` |
| `trace_id` | строка | да | совпадает с `trace_id` в журнале движка |

## Форма `fsm.rejected`

```json
{
  "fsm_id": "light.kitchen_lighting_10",
  "device_id": "light.kitchen",
  "behavior": "lighting",
  "from_state": "ON_MOTION",
  "to_state": null,
  "event": "motion_detected",
  "source": "automatic",
  "timestamp": "2026-10-01T14:23:12.001277",
  "outcome": "rejected",
  "reason": "debounced",
  "trace_id": "a1b2c3d4"
}
```

| `reason` | Когда |
|---|---|
| `unknown_entity` | для идентификатора нет описания автомата |
| `no_state` | описание есть, состояние отсутствует |
| `debounced` | сработала защита от дребезга |
| `no_transition` | из текущего состояния нет перехода по этому событию |
| `guard_failed` | условие перехода не выполнено |

**Различимость обязательна** (FR-004): подписчик получает `outcome: "rejected"`, а не событие с признаком успеха. Отказ и переход в разные состояния — разные события.

## Правила доставки

| Правило | Требование |
|---|---|
| Порядок | не гарантируется (FR-013: доставка неблокирующая) |
| Блокировка | переход автомата **не ждёт** подписчиков (FR-014, SC-015) |
| Ошибка подписчика | изолируется: остальные получают событие, ошибка в журнале, переход не отменяется (FR-003) |
| Потеря при аварии | допустима; источник истины — состояние движка, клиент перечитывает его при подключении (FR-018, FR-028) |
| Форма подписчика | `async def handler(event_type: str, payload: dict, trace_id: str | None = None) -> None`. Синхронные подписчики поддерживаются шиной (R-05), но новые обработчики обязаны быть `async` |
| Обязательные поля | отсутствие `fsm_id` или `to_state` не отменяет доставку: событие уходит с доступными полями + предупреждение в журнале (FR-008) |

## Подписчики и что они делают

| Подписчик | Событие | Действие | Откуда |
|---|---|---|---|
| Хранилище состояний | `fsm.transitioned` | сохраняет новое состояние автомата | новый |
| Зеркало Home Assistant | `fsm.transitioned` | лучшее усилие: записывает состояние во внешнюю систему; ошибка — в журнал | новый |
| Журнал переходов | `fsm.transitioned` | пишет в таблицу `fsm_transitions` | новый |
| Веб-мост | `fsm.transitioned` | формирует живое сообщение и рассылает подписанным соединениям | новый |
| Восстановление состояний | `platform.started` | переносит сохранённые состояния в движок | существующий (`core/fsm/persistence.py:113`), переводится на async |
| Планировщик контекста | `platform.started` | запускает проверку расписаний | существующий (`core/persistence/context_manager.py:86`), переводится на async |
| Метрики | `fsm.transitioned` | счётчик переходов (вне объёма, F3) | существующий мёртвый `record_fsm_transition` |

## Источник перехода (`source`)

| Условие | `source` |
|---|---|
| имя события начинается с `manual_` | `manual` |
| иначе | `automatic` |

Соглашение проверяется тестом по всем шаблонам в `src/features/*.yaml`: события с префиксом `manual_` классифицируются как ручные, остальные — как автоматические. Новые триггеры с этим префиксом подхватываются без изменения кода.

**Ограничение, фиксируется в документации**: это соглашение об именовании, а не проверка приоритетов. Движок приоритетов команд живёт в диспетчере (`CommandIntent.priority`), а движок состояний приоритеты не хранит (R-03).

## Обратная совместимость

| Что | Обещание |
|---|---|
| `FSMPersistence` | переводится на `fsm.transitioned` и async-сигнатуру; поведение (сохранение состояния) сохраняется, но экземпляр по-прежнему не создаётся платформой — источник истины один (`StatePersistence`) |
| `ContextManager` | подписан на `platform.started`, который начинает публиковаться; `ha.state_changed` остаётся непубликуемым — фиксируется как Known Issue |
| Существующие события `device.*`, `state_change` | не меняются |
| Порядок доставки существующих подписчиков | не меняется: `publish` по-прежнему вызывает их последовательно; неблокирующим становится только вызов публикации перехода |
