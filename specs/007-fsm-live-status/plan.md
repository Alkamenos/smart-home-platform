# Implementation Plan: Live FSM Statuses — статусы автоматов в интерфейсе

**Branch**: `007-fsm-live-status` | **Date**: 2026-10-01 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-fsm-live-status/spec.md`

## Summary

Автоматика перестаёт быть «немой»: каждый переход FSM публикуется в шину событий, WebUI перестаёт жить в отдельном мире (одна шина на процесс), состояние автоматов отдаётся по запросу и доставляется в браузер по существующему каналу устройств с проверкой прав, а визуализации перестают показывать выдуманные данные.

Технический подход: инъекция зависимостей в `FSMEngine` (шина, диспетчер, хранилище) вместо текущего «пустого» конструктора; публикация перехода как побочного эффекта `trigger()` в двух точках (успех/отказ); `StatePersistence` как единственный источник истины состояния с зеркалированием в HA через существующий диспетчер; мост «переход → подписка → WebSocket» на канале `/api/v1/ws/devices`; замена выдуманных данных графиков реальными записями `EventStore`.

Побочно устраняются три мёртвых канала (Known Issue #9 / B5, «состояние не сохраняется», «JSON на странице»), обнаруженных при исследовании.

## Technical Context

**Language/Version**: Python 3.12 (репозиторий содержит артефакты и для 3.14; целевая версия — 3.12, см. `pyproject.toml`)

**Primary Dependencies**: FastAPI + Starlette (WebSocket), Pydantic v2, loguru, prometheus_client (вне объёма), sqlite3 (стандартная библиотека, `EventStore`), watchdog (hot-reload, вне объёма)

**Storage**: `data/*.json` (устройства, доступ, синхронизация, состояния автоматов), `data/history.db` (SQLite: `events`, `fsm_transitions`, `manual_overrides`, `ai_suggestions`)

**Testing**: pytest + pytest-asyncio (`asyncio_mode = "auto"`), `--import-mode=importlib`, `pytest-cov` (порог 80% для новых файлов), pytest-playwright (отдельный прогон), mypy `--strict`, ruff

**Target Platform**: Linux-сервер / macOS (Docker Compose), Python 3.12; режимы: автономный (MockAdapter) и с Home Assistant (HAAdapter)

**Project Type**: web-service (FastAPI) + библиотека (ядро) + CLI

**Performance Goals**: доставка живого обновления ≤2 с (SC-003); ответ состояний ≤200 мс на 100 автоматах; публикация перехода не добавляет задержки к самому переходу (SC-015)

**Constraints**: длина функций ≤50 строк, type hints везде, docstrings Google style, loguru с `trace_id`, никаких bare `except`, покрытие ≥80% (критические модули 95%), Core не импортирует Adapters

**Scale/Scope**: ~10–50 автоматов на объект, до 30 одновременных WebSocket-подключений, 4 пользовательские истории, 39 FR

## Обнаруженные дефекты вне буквального объёма спеки

Выявлены при исследовании, **включены в план** как обязательные (без них фича не проверяема end-to-end):

| Дефект | Почему в объёме |
|---|---|
| `FSMEngine` создаётся без диспетчера → `CommandIntent` отбрасываются, автоматика не управляет устройствами (R-01) | FR-016 требует, чтобы команды шли через диспетчер; US3 показывал бы переходы, не влияющие на устройства |
| `FSMEngine` создаётся без хранилища → состояние не сохраняется | FR-015 и SC-016/017 |
| `FSMPersistence` вызывает несуществующий `adapter.set_entity_state` | R-06: путь записи в HA переводится на существующий диспетчер вместо нового метода адаптера |

**Зафиксированы, но НЕ исправляются в этой фиче** (вне объёма, в Known Issues):

| Дефект | Почему не здесь |
|---|---|
| Реестр гвардов/действий движка (`engine._guards`/`_actions`) не используется в производстве | Мёртвый код вне пути данных фичи |
| `MANUAL_SOURCES` в `ManualLockoutMiddleware` недостижим — движок не подставляет `source` | Требует пересмотра приоритетов команд, что выходит за FR-016 |
| `ContextManager` подписан на непубликуемое `ha.state_changed` | Требует публикации событий HA — отдельная задача |
| Метрики FSM no-op, `/metrics` не подключён | Вне объёма спецификации по явному решению (F3) |
| `POST /api/ai/suggestion/{id}/respond` возвращает 500 (лишний аргумент `responded_at`) | Побочный эффект удаления выдумки в US4: раздел без данных больше не предлагает действия, но проверяется, что ответа нет 500 |
| Префикс-коллизия в hot-reload (`config_watcher.py:329` без подчёркивания) | Отдельная задача, не связана с состояниями |
