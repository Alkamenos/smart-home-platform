# План реализации: Интеграция и конфигурирование устройств из Home Assistant

**Ветка**: `001-device-integration` | **Дата**: 2026-09-29 | **Спецификация**: [spec.md](spec.md)

**Исходные данные**: Спецификация функции из `/specs/001-device-integration/spec.md`

## Резюме

Реализация интеграции с Home Assistant для загрузки и конфигурирования устройств в Smart Home Platform. Функция обеспечивает синхронизацию устройств из HA через REST API с возможностью редактирования параметров, синхронизацией состояния в реальном времени через WebSocket и управлением доступом к устройствам. Основной фокус P1 на загрузку и конфигурирование, P2 возможности (управление состоянием, доступ) реализуются во втором этапе.

## Технический контекст

**Язык/Версия**: Python 3.10+ (текущая версия 3.14.6)

**Основные зависимости**: 
- Pydantic v2 (валидация схем)
- Loguru (логирование)
- asyncio (асинхронность)
- aiohttp или requests (HTTP клиент для HA API)
- websockets (WebSocket для синхронизации состояния)

**Хранилище**: JSON-based state persistence (совместимо с текущей архитектурой)

**Тестирование**: pytest с интеграционными и юнит тестами

**Целевая платформа**: Linux сервер (как и основной проект)

**Тип проекта**: Веб-приложение с CLI интерфейсом

**Цели производительности**: 
- Загрузка устройств: < 1 минута для типичной установки HA (100-500 устройств)
- Синхронизация состояния: <= 5 секунд задержка
- Переподключение при сбое: <= 30 секунд

**Ограничения**: 
- Надежная синхронизация состояния при потере соединения
- Корректная обработка одновременных операций редактирования
- Безопасность: только администраторы могут конфигурировать источники HA

**Масштаб/Объем**: 
- Типичная установка HA: 100-500 устройств
- Одновременные пользователи: 1-10 администраторов
- Количество конечных пользователей: 2-50

## Phase 1: Проектирование и контракты

### Исходные требования

Базируется на Phase 0 исследованиях

### 1. Модель данных (data-model.md)

**Основные сущности**:

```
HASource (Источник Home Assistant)
├── id: UUID
├── name: str
├── url: str
├── token: str (encrypted)
├── status: "connected" | "disconnected" | "error"
├── last_sync: datetime
├── error_message: str | None
└── created_at: datetime

Device (Устройство)
├── id: UUID
├── ha_entity_id: str
├── name: str
├── type: str
├── model: str
├── manufacturer: str
├── state: dict
├── config: DeviceConfig
├── source_id: UUID (ref to HASource)
├── status: "available" | "unavailable" | "removed_from_ha"
├── last_state_update: datetime
└── created_at: datetime

DeviceConfig (Конфигурация устройства)
├── id: UUID
├── device_id: UUID
├── display_name: str
├── description: str
├── location: str
├── tags: List[str]
├── user_id: UUID (кто создал конфигурацию)
└── updated_at: datetime

DeviceCommand (Команда устройства)
├── id: UUID
├── device_id: UUID
├── name: str
├── ha_service: str
├── parameters: Dict[str, Parameter]
└── description: str

Parameter (Параметр команды)
├── name: str
├── type: str
├── required: bool
├── allowed_values: List | None
└── default: Any | None

DeviceSyncEvent (События синхронизации)
├── id: UUID
├── device_id: UUID
├── type: "state_changed" | "config_changed" | "command_sent"
├── timestamp: datetime
├── details: dict
└── user_id: UUID | None
```

**Отношения**:
- HASource -> Device (1:N) - один источник содержит много устройств
- Device -> DeviceConfig (1:1) - каждое устройство имеет одну конфигурацию
- Device -> DeviceCommand (1:N) - устройство может иметь много команд
- Device -> DeviceSyncEvent (1:N) - логирование всех операций

**Правила валидации**:
- URL HASource должен быть валидный HTTP/HTTPS URL
- Token не должен храниться в открытом виде (шифрование)
- DeviceConfig.display_name должна быть уникальной в пределах источника
- DeviceCommand.ha_service должна соответствовать формату HA сервис

### 2. Контракты интеграции (contracts/)

**REST API контракты**:
- `POST /api/devices/sources` - добавление источника HA
- `GET /api/devices/sources` - список источников
- `GET /api/devices/sources/{id}` - получение источника
- `POST /api/devices/sources/{id}/sync` - запуск синхронизации
- `GET /api/devices` - список всех устройств
- `GET /api/devices/{id}` - получение устройства с полной информацией
- `PUT /api/devices/{id}/config` - обновление конфигурации
- `POST /api/devices/{id}/command` - отправка команды
- `GET /api/devices/{id}/events` - история операций

**WebSocket контракт** (синхронизация состояния):
- Подписка на изменения: `{"action": "subscribe", "device_ids": [...]}`
- Событие изменения: `{"type": "device_state_changed", "device_id": "...", "state": {...}, "timestamp": "..."}`

### 3. Руководство быстрого запуска и валидации (quickstart.md)

**Сценарии валидации**:

1. **Базовая интеграция**: Подключение к HA и загрузка устройств
   - Предусловие: HA работает, доступен по сети
   - Команды: Добавить источник, запустить синхронизацию
   - Результат: Устройства загружены и видны в интерфейсе

2. **Конфигурирование**: Редактирование параметров устройства
   - Предусловие: Устройства загружены
   - Команды: Отредактировать название, описание, теги
   - Результат: Изменения сохранены и сохраняются при перезагрузке

3. **Синхронизация состояния**: WebSocket обновление состояния
   - Предусловие: HA подключена, WebSocket установлено
   - Команды: Изменить состояние устройства в HA
   - Результат: Изменение синхронизируется в платформе <= 5 сек

4. **Обработка ошибок**: Сбой соединения и восстановление
   - Предусловие: HA была доступна
   - Команды: Отключить HA (симуляция)
   - Результат: Система показывает ошибку, переподключается автоматически

5. **Управление доступом** (P2):
   - Предусловие: Система поддерживает роли
   - Команды: Назначить доступ к устройству
   - Результат: Только авторизованные пользователи видят устройство
