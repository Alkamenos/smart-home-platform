# Data Model: Device Lifecycle

**Feature**: specs/006-device-lifecycle | **Дата**: 2026-09-30

Сущности описаны в терминах предметной области. Изменения существующих моделей минимальны: схема манифеста и формат хранения **не меняются** (миграции не требуются, конституция V).

---

## 1. Устройство (Device) — единственный источник: сервис устройств + постоянное хранилище

| Атрибут | Тип | Правила |
|---|---|---|
| `id` | UUID | генерируется при создании, неизменен; ключ в постоянном хранилище |
| `ha_entity_id` | строка | формат `domain.object_id` (обязательный, уникальный в пределах источника — FR-008: повторное добавление обновляет, а не плодит) |
| `source_id` | UUID | **обязателен** (D-009): устройство принадлежит источнику; выбирается при добавлении вручную |
| `name` | строка | 1…255 символов |
| `device_type` | строка | одно из значений, поддерживаемых шаблонами платформы (`light`, `climate`, `ventilation`, `sensor`, `switch`) |
| `model`, `manufacturer` | строка \| null | необязательные |
| `ha_area_id` | строка \| null | область Home Assistant |
| `state` | объект | текущее состояние (`{"state": "on", ...}`) — обновляется событиями |
| `attributes` | объект | дополнительные атрибуты состояния |
| `config` | объект \| null | пользовательская конфигурация: `display_name`, `description`, `location`, `tags` |
| `status` | перечисление | `available` (по умолчанию) \| `unavailable` \| `removed_from_ha` (D-010) |
| `last_state_update` | дата-время | время последнего подтверждённого состояния |
| `created_at`, `updated_at` | дата-время | заполняются автоматически |

**Связи**: источник (many-to-one) → устройство; устройство → записи о доступе; устройство → машины состояний (0…N); устройство → записи жизненного цикла (0…N).

**Правила валидации** (нарушение → отказ с указанием причины, FR-007):
1. `ha_entity_id` соответствует шаблону `domain.object_id` (нижний регистр, точка обязательна).
2. `name` не пустой, ≤255 символов.
3. `source_id` существует в списке источников.
4. Поведения: 0…N; для каждого — существующий шаблон, приоритет ≥1, уникальность пары «шаблон + приоритет» в пределах устройства (иначе идентификатор машины состояний совпадёт — FR-018).
5. Не более 10 тегов, каждый ≤50 символов (существующее правило конфигурации).

**Индексация** (для поиска): по `source_id`, `device_type`, `ha_entity_id`, `status`. Удаление устройства убирает его из всех индексов.

---

## 2. Поведение (Behavior) — часть конфигурации, живёт в манифесте

| Атрибут | Тип | Правила |
|---|---|---|
| `template` | строка | имя существующего шаблона автоматизации (не произвольная строка из интерфейса) |
| `priority` | целое | ≥1; меньше — выше приоритет; уникально в пределах устройства |
| `params` | объект | параметры шаблона; при наличии `motion_sensor` проверяется, что датчик принадлежит известной комнате |

**Производное поле (не хранится)**: идентификатор машины состояний `{ha_entity_id}_{template}_{priority}` — определяется фабрикой, служит ключом регистрации в движке.

## 3. Источник данных (Source)

| Атрибут | Тип | Правила |
|---|---|---|
| `id` | UUID | неизменен |
| `name` | строка | 1…255 символов |
| `url` | строка | адрес Home Assistant (нормализуется: без завершающего слэша) |
| `token` | строка | ≥10 символов, шифруется при сохранении |
| `status` | перечисление | `disconnected` (по умолчанию) \| `connected` \| `error` |
| `last_sync` | дата-время \| null | последняя успешная синхронизация |
| `last_error` | строка \| null | последняя ошибка подключения/синхронизации |
| `device_count` | целое | устройств загружено из источника |

**Связи**: источник → устройства; источник → мастер (поиск и применение).

## 4. Машина состояний (FSM) — исполняемая автоматика

| Атрибут | Тип | Правила |
|---|---|---|
| `entity_id` | строка | `{ha_entity_id}_{template}_{priority}`, детерминированно (ADR-003) |
| `target_device_id` | строка | устройство-владелец; в действия передаётся реальный идентификатор устройства, а не идентификатор автоматики |
| `definition` | определение FSM | загружается из шаблона + `params`; **структура не изменяется фичей** (конституция I) |
| `state` | строка | текущее состояние автоматики; сбрасывается в начальное при снятии/пересоздании |
| `timers` | набор задач | не более одной активной задачи таймаута на автоматику; отменяются при снятии |

**Правила жизненного цикла** (FR-014…018):
- Создание: только для устройства, присутствующего в манифесте; выполняется после успешной записи в постоянное хранилище.
- Снятие: при удалении устройства, при переводе в `removed_from_ha`, при изменении состава поведений.
- Повторное применение: снятие → создание (полная замена), что гарантирует отсутствие дублей и чистоту таймеров.
- Маршрутизация: после любого изменения состава устройств карта «датчик → автоматика» перестраивается целиком.

## 5. Запись о доступе (Device Access)

| Атрибут | Тип | Правила |
|---|---|---|
| `id` | UUID | неизменен |
| `device_id` | UUID | устройство; запись выдаётся **до** появления устройства (device-blind grant, отклонение спеки 004) |
| `user_id` | строка | идентификатор пользователя |
| `role` | перечисление | `viewer` < `controller` < `admin` |
| `granted_by` | строка \| null | кто выдал |
| `created_at` | дата-время | — |

**Каскад при удалении устройства**: все записи устройства отзываются (FR-026) — иначе удалённое устройство возвращалось бы в списки как доступное.

## 6. Запись жизненного цикла (Sync Event) — аудит

| Атрибут | Тип | Правила |
|---|---|---|
| `device_id` | UUID | устройство (nullable для событий уровня источника) |
| `event_type` | перечисление | `device_added`, `device_updated`, `device_deleted`, `device_archived`, `device_restored`, `devices_applied`, `config_changed`, `access_granted`, `access_updated`, `access_revoked`, `command_executed` |
| `before` / `after` | объект | снимок изменяемых полей (только реально изменённые) |
| `created_at` | дата-время | — |

Хранение: append-only журнал (существующий механизм). Правила: `config_changed` содержит только изменённые поля; ошибка записи аудита не должна приводить к потере результата операции — фиксируется предупреждение.

## 7. Переходы статусов устройства

```text
                 добавление / синк нашёл
        ┌──────────────────────────────────────┐
        │                                      ▼
   (нет) ───────────────► available ──────────► unavailable
                            │   ▲                │
             исчез в HA     │   │ событие       │ событие
                            ▼   │ подтверждено   │
                      removed_from_ha ◄───────────┘
                            │   (повторно появился в HA)
                            └──► (восстановление → available)
```

| Переход | Инициатор | Побочные эффекты |
|---|---|---|
| — → `available` | добавление устройства; успешная синхронизация | создание машин состояний, обновление времени последнего состояния |
| `available` → `unavailable` | 60 секунд без подтверждения состояния | метрики, аудит |
| `unavailable` → `available` | событие состояния | сброс таймера недоступности |
| `available` → `removed_from_ha` | синк не нашёл устройство в источнике | **снятие машин состояний**, исключение из активной автоматики, сохранение конфигурации и прав |
| `removed_from_ha` → `available` | устройство снова найдено в источнике | пересоздание машин состояний |
| любое → удаление | явное действие администратора | снятие машин состояний, отзыв прав, удаление из хранилища и индексов, запись в манифест, аудит |

## 8. Операции над манифестом и их откат

| Операция | Что меняется в манифесте | Откат |
|---|---|---|
| Добавление устройства | устройство добавляется в комнату (или новую комнату) | восстановление снимка манифеста (существующий механизм резервной копики) |
| Изменение устройства | поля устройства и его поведения | восстановление снимка |
| Перемещение между комнатами | удаление из исходной комнаты, добавление в целевую | восстановление снимка |
| Удаление устройства | устройство удаляется из комнаты | восстановление снимка |
| Применение из мастера | добавление выбранных устройств в существующие или новые комнаты | восстановление снимка; повторное применение тех же данных не создаёт дублей |

**Правило порядка** (D-012): манифест → постоянное хранилище → runtime (кэш/индекс) → машины состояний → маршрутизация → аудит. Ошибка записи в хранилище приводит к откату манифеста; ошибка на шаге машин состояний не откатывает данные, а фиксируется событием с признаком частичного успеха.
