Пошаговые сценарии, доказывающие работоспособность фичи. Сценарии 1–6 проверяются без Home Assistant; 7–8 требуют доступного источника (устройства можно подменить).

## Сценарий 1. Добавление устройства через интерфейс — устройство появляется сразу

**Что проверяет**: FR-001, FR-003, FR-004, SC-001, US1.

1. Запустить платформу в автономном режиме:
   ```bash
   PYTHONPATH=src python3 -m src.main
   ```
   Ожидается в логах `Platform is ready and listening on port 8125`.
2. Открыть `http://127.0.0.1:8125/`, нажать **Add Devices** (мастер).
3. Если источников нет — создать источник через форму (имя, адрес, токен).
4. Взять идентификатор любого существующего устройства (например `light.kitchen`).
5. На главной странице: **Add Device** в комнате → заполнить `device_id=light.kitchen`, тип `light`, имя → **Save Device**.
6. Проверить список устройств: `GET /api/v1/devices` содержит `light.kitchen`.

**Ожидаемые результаты**:
- устройство видно в списке **сразу**, без перезапуска;
- повторный запуск сервера → устройство осталось в списке;
- в истории устройства есть запись о добавлении.

**Команда для проверки без браузера:**
```bash
curl -s -H "X-User-ID: admin_user" -H "X-Is-Admin: true" \
  http://127.0.0.1:8125/api/v1/devices | python3 -m json.tool
```

## Сценарий 2. Применение одной точки: дубля маршрута нет

**Что проверяет**: FR-005, FR-008, US1.

1. Выполнить применение одного и того же набора дважды:
   ```bash
   SOURCE_ID=<id источника>
   PAYLOAD='{"source_id":"'"$SOURCE_ID"'","selections":[{"ha_entity_id":"light.kitchen","device_type":"light","name":"Кухонный свет","behaviors":[{"template":"lighting","priority":10,"params":{}}]}],"dry_run":false}'

   curl -s -X POST -H "Content-Type: application/json" \
     -H "X-User-ID: admin_user" -H "X-Is-Admin: true" \
     -d "$PAYLOAD" http://127.0.0.1:8125/api/v1/devices/apply

   curl -s -X POST -H "Content-Type: application/json" \
     -H "X-User-ID: admin_user" -H "X-Is-Admin: true" \
     -d "$PAYLOAD" http://127.0.0.1:8125/api/v1/devices/apply
   ```
2. Сравнить длину списка устройств до и после второго вызова.

**Ожидаемые результаты**:
- оба ответа содержат `success: true`;
- количество устройств **не увеличилось** после второго вызова (SC-005);
- количество машин состояний для устройства — одна на каждое поведение (нет дублей автоматики, FR-018).

## Сценарий 3. Устройство оживает без рестарта

**Что проверяет**: FR-014…FR-017, SC-002, US1.

1. Убедиться, что источник датчиков настроен: в манифесте у комнаты есть сенсор движения (например `binary_sensor.kitchen_motion`).
2. Добавить устройство с поведением `lighting` и параметром `motion_sensor=binary_sensor.kitchen_motion`, приоритет 10.
3. **Без перезапуска** имитировать событие датчика через адаптер (в mock-режиме) либо включить/выключить датчик в Home Assistant (если источник доступен).
4. Проверить, что по устройству прошла команда и его состояние обновилось.

**Проверка реакции на датчик в mock-режиме** (через контейнер приложения, без UI):
```python
# в python-консоли с PYTHONPATH=src
from core.container import Container

c = Container(manifest_path="instances/leonids_house/manifest.yaml")
ctx = c.build()
print(ctx.event_router.get_mapping_for_sensor("binary_sensor.kitchen_motion"))
```
Ожидается: список маппингов **содержит** идентификатор автоматики нового устройства (т.е. карта перестроилась).

**Ожидаемые результаты**:
- маппинг «датчик → автоматика» содержит новое устройство до перезапуска;
- событие датчика вызывает переход автоматики и отправку команды;
- в журнале нет предупреждений о ненайденных автоматиках.

## Сценарий 4. Синхронизация и список согласованы

**Что проверяет**: FR-019…FR-023, SC-005, US3.

1. Создать источник и запустить синхронизацию (при недоступном источнике ожидается `500` с понятной причиной — предыдущие устройства должны сохраниться).
2. При доступном источнике: выполнить синхронизацию, затем запросить список устройств.
3. Повторить синхронизацию трижды, каждый раз сверяя количество устройств.

**Ожидаемые результаты**:
- устройства из источника появились в списке **без перезапуска**;
- количество устройств не растёт при повторных синках (SC-005);
- время последней синхронизации обновлено; при недоступном источнике видна причина ошибки, устройства не потеряны.

## Сценарий 5. Устройство, исчезнувшее из источника

**Что проверяет**: FR-022, D-010.

1. Синхронизировать источник, содержащий устройство A (устройство видно, автоматика работает).
2. Изменить на стороне источника состав так, чтобы устройства A не было.
3. Снова синхронизировать.

**Ожидаемые результаты**:
- устройство A остаётся в списке, но со статусом `removed_from_ha`;
- автоматика устройства A снята: маппингов для него нет, команды не отправляются;
- конфигурация и права устройства сохранены;
- если устройство снова появится в источнике — статус возвращается в `available`, автоматика пересоздана.

## Сценарий 6. Удаление устройства

**Что проверяет**: FR-024…FR-027, SC-006, US4.

1. Добавить устройство с поведением (см. сценарий 3).
2. Удалить его через интерфейс (действие «Удалить») или командой:
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" -X DELETE \
     -H "X-User-ID: admin_user" -H "X-Is-Admin: true" \
     http://127.0.0.1:8125/api/v1/devices/<device_id>
   ```
3. Повторить удаление (проверка идемпотентности).
4. Имитировать событие датчика, связанного с удалённым устройством.
5. Перезапустить сервер и запросить список устройств.

**Ожидаемые результаты**:
- `204` при первом удалении и `204` при повторном;
- устройства нет в списке, в манифесте и в истории доступа;
- событие датчика не вызывает команд удалённому устройству и не даёт ошибок в журнале (SC-006);
- после перезапуска устройство не появляется.

## Сценарий 7. Мастер находит реальные устройства

**Что проверяет**: FR-010…FR-013, SC-003, SC-004, US2. **Требуется доступный источник Home Assistant.**

1. Открыть мастер, выбрать источник, нажать **Сканировать**.
2. Проверить: список устройств непуст, признак «применить автоматически» различается у устройств, фильтры соответствуют категориям платформы.

**Ожидаемые результаты**:
- показаны реальные устройства источника с именами, областями, состояниями;
- при недоступном источнике — сообщение с причиной, а не «устройств нет» (FR-013);
- в сетевом журнале браузера у запросов есть заголовки `X-User-ID`/`X-Is-Admin` (FR-009);
- в консоли браузера нет синтаксических ошибок и страница не содержит «осиротевших» блоков скриптов.

## Сценарий 8. Применение из мастера — устройство сразу работает

**Что проверяет**: FR-012, FR-014, SC-001, SC-002, US2. **Требуется доступный источник.**

1. В мастере отметить 1–2 устройства, назначить комнату, выполнить **Тестовый запуск** — убедиться, что ничего не изменилось.
2. Нажать **Применить**; дождаться результата (сообщение не должно исчезать само).
3. Открыть главную страницу и список устройств.
4. Имитировать событие датчика для поведения применённого устройства.

**Ожидаемые результаты**:
- предпросмотр не изменил манифест и список;
- после применения устройства появились в списке и **реагируют на событие** без перезапуска;
- невыбранные устройства не появились;
- повторное применение того же набора не создало дублей.

## Сценарий 9. Автономный режим (без Home Assistant)

**Что проверяет**: конституционный принцип VI, допущения спеки.

1. Запустить без переменных `HA_TOKEN`/`HA_WEBSOCKET_URL`: `PYTHONPATH=src python3 -m src.main`.
2. Выполнить сценарии 1, 2, 3, 6 (добавление, идемпотентность, оживление, удаление).
3. Открыть мастер без источника.

**Ожидаемые результаты**:
- добавление, правка, удаление и реакция автоматики на события работают;
- мастер показывает «источник недоступен» с причиной, а не ошибку 500;
- синхронизация и команды к Home Assistant завершаются понятной ошибкой, не ломая остальную работу.
