# Phase 1 — Data Model: Веб-интерфейс инженера «Дом»

Сущности, которыми оперирует интерфейс. Поля приведены как смысловые (что показываем и
какие правила), а не как схемы хранения. Источник большинства данных — существующие модели
платформы (манифест, состояния движка, журнал, наблюдение за локациями, спека 016).

## Локация (`Location`)

Комната или особая зона.

| Поле | Смысл | Правила |
|---|---|---|
| `id` | Идентификатор | Из манифеста; уникален |
| `name` | Отображаемое имя | Русское, из манифеста |
| `kind` | Вид: `room` / особая зона | Комнаты манифеста → автоматически `room` |
| `readings` | Показания по ролям | Список: у роли бывает несколько датчиков |
| `derived` | Производные | Присутствие, время с последнего движения, открытые окна/двери, число доступных и молчащих датчиков |
| `status` | Сводный статус | `ok` / `attention` (есть тревоги) |

**Правила**: мёртвый (недоступный) датчик не участвует в производных (FR-010). Отсутствие
датчиков — это «данных нет», а не ноль.

## Показание (`Reading`)

Значение датчика в роли.

| Поле | Смысл | Правила |
|---|---|---|
| `role` | Роль (температура, влажность, движение, контакт, дождь, почва, свет и др.) | Роль известна маршрутизатору, иначе датчик не в подписке |
| `entity_id` | Сущность Home Assistant | Для деталей и истории |
| `value` | Значение | Может отсутствовать |
| `unit` | Единица измерения | Приходит из HA; без неё значение не сравнимо |
| `at` | Время показания | Для относительного времени |
| `stale` | «Молчит» | Превышен порог наблюдения |
| `unavailable` | «Недоступен» | HA не отвечает |

**Правила**: `stale` и `unavailable` — разные состояния и показываются раздельно (FR-007,
FR-011). Значение недоступного/молчащего датчика не показывается как текущее (SC-010).

## Устройство (`Device`)

| Поле | Смысл | Правила |
|---|---|---|
| `id` | Идентификатор | UUID платформы |
| `name` / `display_name` | Отображаемое имя | Человеческое, из манифеста/HA |
| `ha_entity_id` | Сущность HA | |
| `device_type` | Тип (light, switch, fan, cover, climate, …) | Определяет доступные действия |
| `actual_state` | Фактическое состояние | Из HA |
| `status` | Доступность | `available` / `unavailable` |
| `fsm` | Состояния автоматов | Список `FSMState` |
| `behaviors` | Поведения | Шаблон, приоритет, параметры |
| `automation` | Наличие автоматики | Отличать «не настроена» от «сервис недоступен» |

## Состояние автомата (`FSMState`)

| Поле | Смысл |
|---|---|
| `fsm_id` | `{устройство}_{шаблон}_{приоритет}` |
| `behavior` | Имя поведения (шаблон) |
| `state` | Текущее состояние |
| `since` | Время последнего перехода (ISO-8601) |
| `device_id` | Устройство автомата |

## Решение (`Decision`)

Последнее решение автоматики по устройству.

| Поле | Смысл | Правила |
|---|---|---|
| `outcome` | `on` / `off` / `denied` / `no_command` | Отображается человеческим языком |
| `reason_text` | Причина | Без имён констант (FR-018) |
| `at` | Время | Относительное («3 минуты назад») |

## Ручная блокировка (`Override`)

| Поле | Смысл |
|---|---|
| `device` / `entity` | Кого касается |
| `expires_at` | Когда автоматика вернётся |
| `active` | Активна ли сейчас |

## Команда (`Command`)

| Поле | Смысл | Правила |
|---|---|---|
| `name` | Действие (`turn_on`, `turn_off`, режим, положение) | Определяется типом устройства |
| `state` | Состояние команды | `pending` / `done` / `failed` |
| `automation_synced` | Учла ли автоматика | Показывается явно (FR-016) |
| `error` | Причина отказа | Показывается, не «молчит» (FR-015) |

## Событие журнала (`JournalEvent`)

| Поле | Смысл | Правила |
|---|---|---|
| `at` | Время | |
| `level` | Уровень | Для фильтра |
| `entity_id` / `device` / `location` | Источник | Для фильтра |
| `role` | Роль (для датчиков локации) | Подставляется при чтении |
| `message` | Что произошло | Человекочитаемо |
| `trace_id` | Трассировка | Для поиска цепочки «событие → решение → команда → результат» |
| `old_value` / `value` | Было / стало | Для показаний |

## Тревога (`Alert`)

Вычисляемое отклонение, требующее внимания (FR-011).

| Поле | Смысл | Правила |
|---|---|---|
| `kind` | `stale_sensor` / `unavailable` / `automation_mismatch` | |
| `subject` | Датчик/устройство/локация | |
| `severity` | `warning` / `info` | |
| `detail` | Человеческое объяснение | Без констант |
| `at` | Время появления | |

## Источник (`Source`)

Подключение Home Assistant.

| Поле | Смысл |
|---|---|
| `id`, `name` | Идентификация |
| `status` | Синхронизирован / рассинхронизирован / недоступен |
| `entities` | Доступные сущности для импорта |

## Сессия (`Session`)

Кто смотрит и что ему можно.

| Поле | Смысл |
|---|---|
| `user_id` | Из заголовка запроса |
| `is_admin` | Из заголовка запроса |
| `display_name` | Отображаемое имя, если известно |

## Связи

- Локация 1—N Показание (по ролям).
- Устройство 1—N Состояние автомата; Устройство 1—N Поведение.
- Устройство 1—N Решение; Устройство 0—1 активная Ручная блокировка.
- Локация/Устройство 1—N Событие журнала (через сущности).
- Alert ссылается на датчик (Показание) или устройство.
- Источник 1—N Устройство.

## Переходы состояний

- **Показание**: `значение` → (`stale` | `unavailable` | `значение`) — по времени и ответу HA.
- **Устройство**: `actual_state` меняется по событиям HA; `status` — по доступности.
- **Команда**: `pending` → (`done` | `failed`); отображается оптимистично до подтверждения.
- **Автомат**: переходы из движка; интерфейс только отражает.
