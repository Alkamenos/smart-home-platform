# Data Model: Health Check дома

**Feature**: `019-house-health-check` | **Date**: 2026-11-09

## 1. HouseProblem — проблема дома

Одна причина по одной сущности. В интерфейсе и уведомлении причины одной
сущности группируются в одну строку.

| Поле | Тип | Правила |
|---|---|---|
| `id` | строка | стабильный: `sha1(kind + subject)`; не меняется между обходами |
| `kind` | enum | `stale`, `low_battery`, `battery_silent`, `unavailable`, `missing_entity`, `house_unreadable`, `command_not_applied`, `device_mismatch`, `fsm_stuck`, `ha_disconnected` |
| `subject` | строка\|null | сущность или прибор; `null` только для `house_unreadable` |
| `name` | строка | человеческое имя |
| `area` | строка | комната/локация; пусто, если неизвестно |
| `level` | enum | `info`, `warning`, `critical` |
| `detail` | строка | причина человеческим языком, без технического шума |
| `source` | enum | `health`, `watchdog`, `command` |
| `value` | строка\|null | показание/заряд на момент обнаружения |
| `first_seen` | ISO-8601 | первый обход, где проблема появилась; сохраняется |
| `last_seen` | ISO-8601 | последний обход, где проблема подтвердилась |
| `closed_at` | ISO-8601\|null | время снятия; `null` для активной |
| `close_reason` | строка\|null | `recovered`, `entity_removed`, `manual_dismiss` |

**Правила:**

- Активная проблема — `closed_at = null`.
- Один `kind` + `subject` = одна активная запись; повторный обход обновляет
  `last_seen`, а не создаёт дубль.
- Если причина исчезла, запись закрывается на ближайшем обходе с
  `close_reason = recovered`.
- Закрытые записи хранятся 30 дней, затем удаляются.
- `first_seen` не переписывается при перезапуске.
- Уровни: `critical` — дом не прочитан, нет связи, датчик безопасности молчит,
  команда не применена к критичному прибору; `warning` — молчание, низкий
  заряд, расхождение; `info` — отсутствующая сущность, которую можно убрать из
  манифеста.

**Состояния:**

```text
        появилась причина
                │
                ▼
            ┌───────┐   причина исчезла   ┌────────┐
            │ open  │ ──────────────────► │ closed │
            └───────┘                     └────────┘
                │                             │
                │ причина подтвердилась       │ 30 дней
                └── last_seen = now           ▼
                                          удалена
```

## 2. ProblemGroup — представление для человека

Не хранится, собирается из активных `HouseProblem`:

| Поле | Тип | Правила |
|---|---|---|
| `subject` | строка | сущность/прибор |
| `name` | строка | имя |
| `area` | строка | место |
| `level` | enum | максимум из уровней причин |
| `reasons` | список | `{kind, detail, level, first_seen, last_seen}` |
| `first_seen` | ISO-8601 | минимум по причинам |

Правило: одна строка на сущность; причины перечислены внутри, а не дублируют
строку.

## 3. SensorExpectation — ожидание по датчику

| Поле | Тип | Правила |
|---|---|---|
| `entity_id` | строка | сущность из манифеста |
| `expected_interval_sec` | число | > 0; медиана интервалов за 7 дней |
| `stale_after_sec` | число | ≥ 2 часа для активных; 48 часов для батарейки |
| `source` | enum | `history`, `class`, `manifest` |
| `samples` | int | сколько интервалов легло в медиану |
| `updated_at` | ISO-8601 | когда пересчитано |

**Правила:**

- Для активных датчиков: `stale_after = max(2 × expected_interval, 2 ч)`.
- Для батарейки: `stale_after = 48 ч` независимо от истории.
- Для событийных датчиков (движение, контакт, дверь): молчание не проблема,
  если датчик не отчитывается периодически; порог 24 ч применяется только к
  датчикам безопасности (дым, газ, протечка).
- Если история пуста: `source = class`, интервал по таблице из `research.md`.

## 4. CommandExpectation — ожидание применения команды

| Поле | Тип | Правила |
|---|---|---|
| `device_id` | строка | прибор |
| `service` | строка | `turn_on`, `turn_off`, `open_cover`, ... |
| `expected_state` | enum | `on`, `off`, `open`, `closed` |
| `sent_at` | ISO-8601 | время отправки |
| `expires_at` | ISO-8601 | `sent_at + 5 минут` (настраивается) |
| `status` | enum | `pending`, `applied`, `failed` |

**Правила:**

- Записывается только реально отправленная команда (не заблокированная
  локкаутом и не отклонённая).
- Новая команда по тому же прибору заменяет прежнее ожидание.
- `applied` — состояние совпало до истечения; `failed` — не совпало спустя
  допуск.
- Переходные состояния (`opening`, `closing`, `transition`) не считаются
  провалом; ожидание ждёт устойчивого состояния.
- Если состояние прибора не читается, ожидание переводится в `unknown` и не
  создаёт проблему.

## 5. HealthCheckRun — один обход

| Поле | Тип | Правила |
|---|---|---|
| `started_at` | ISO-8601 | начало |
| `finished_at` | ISO-8601 | конец |
| `scope_count` | int | сколько сущностей проверено |
| `problems_count` | int | сколько активных проблем найдено |
| `result` | enum | `ok`, `problems`, `unknown` |
| `error` | строка\|null | причина `unknown` |

**Правила:** при пустом ответе Home Assistant `result = unknown`; проблемы
«молчит» в этом обходе не создаются и не закрываются.

## 6. NotificationState — состояние уведомления

| Поле | Тип | Правила |
|---|---|---|
| `fingerprint` | строка | хэш отсортированного списка `(kind, subject, detail)` |
| `last_sent_at` | ISO-8601\|null | последнее создание/обновление |
| `last_count` | int | число проблем на момент отправки |
| `active` | bool | уведомление сейчас показано |
| `dirty` | bool | HA был недоступен, нужно повторить |

**Правила:**

- `fingerprint` изменился → отправить/обновить сразу.
- `fingerprint` тот же и `active` → не отправлять; если прошло 24 часа и
  проблемы живы — одно обновление.
- Список пуст и `active` → `dismiss`.
- `dirty` сохраняется между перезапусками, чтобы не потерять уведомление.

## 7. Файлы состояния

```json
{
  "version": 1,
  "problems": [ { "id": "...", "kind": "stale", "...": "..." } ],
  "closed": [ { "id": "...", "closed_at": "...", "close_reason": "recovered" } ],
  "notification": { "fingerprint": "...", "last_sent_at": "...", "active": true, "dirty": false },
  "expectations": { "sensor.temperature": { "expected_interval_sec": 900, "source": "history" } }
}
```

Файл `health_problems.json` в `DATA_PATH`; запись через временный файл и
`os.replace`, чтение с версией схемы; при повреждении — пустое состояние и
предупреждение в журнале (не падать).

## 8. Связь с API

`GET /api/v1/problems`:

```json
{
  "generated_at": "2026-11-09T12:00:00+05:00",
  "count": 3,
  "levels": {"info": 0, "warning": 2, "critical": 1},
  "problems": [
    {
      "id": "…",
      "kind": "stale",
      "subject": "sensor.datchik_temperatury_spalnia_temperature",
      "name": "Спальня температура",
      "area": "Спальня",
      "level": "warning",
      "detail": "молчит 2.4 ч при ожидании 30 мин",
      "source": "health",
      "first_seen": "2026-11-09T11:00:00+05:00",
      "last_seen": "2026-11-09T12:00:00+05:00",
      "reasons": []
    }
  ]
}
```

`GET /api/v1/health` сохраняет поля `generated_at`, `sensor_count`, `areas` и
дополнительно отдаёт `count`, `levels`, `problems` по датчикам (совместимо).

## 9. Валидация

- `first_seen <= last_seen`; `closed_at >= first_seen`.
- `stale_after_sec >= 7200` для активных датчиков; `= 172800` для батарейки.
- `expected_interval_sec > 0`; `samples >= 0`.
- `low_battery_percent` в диапазоне 0–100.
- `level` только из перечисления.
- `fingerprint` — стабильный хэш, не зависит от порядка проблем.
- Время — ISO-8601 с часовым поясом дома.

## 10. Миграция и совместимость

- Первый запуск: файла нет → пустое состояние, все проблемы создаются заново с
  `first_seen = now`.
- Версия схемы выше ожидаемой → файл не читается, предупреждение, пустое
  состояние (данные не теряем молча — пишем в журнал).
- Старые поля `last_report` не меняются: дашборд и `/api/v1/observation`
  продолжают работать.
