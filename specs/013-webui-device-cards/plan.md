# План реализации: Карточки дома — состояние, причина и управление

**Ветка**: `013-webui-device-cards` | **Дата**: 2026-10-09 | **Спека**: [spec.md](./spec.md)

**Вход**: спецификация из `specs/013-webui-device-cards/spec.md`

## Краткое содержание

Карточка комнаты начинает показывать живое состояние устройств и датчиков (из
Home Assistant, одним запросом с кэшем), состояние автомата и **причину** последнего
решения (движок начинает запоминать её — сегодня она есть только в журнале), а также
переключатель состояния через уже существующий endpoint команд. Разметка и стили
переезжают в отдельный партиал, интерфейс переводится на русский, добавляется
обновление по событиям FSM с поллингом-страховкой.

Ключевое: **новая механика только одна** — хранение последнего решения в движке. Всё
остальное переиспользует то, что уже работает.

## Технический контекст

**Язык/версия**: Python 3.12 (боевой контейнер), Jinja2 + HTMX + Bootstrap 5 + Bootstrap
Icons в веб-интерфейсе.

**Основные зависимости**: FastAPI, Jinja2, HTMX, Bootstrap 5, loguru, aiohttp/websockets
(доступ к Home Assistant), pytest + pytest-asyncio.

**Хранилище**: новое хранилище не требуется. Последнее решение автомата живёт в памяти
процесса — карточка отвечает на вопрос «почему **сейчас**», а не «что было вечером»
(см. research.md §3).

**Тестирование**: pytest; для шаблонов — проверки рендеринга на подставных данных
(карточка обязана показывать название, состояние и причину), для механики решения —
проверки движка, для команд — существующий набор `test_device_behaviors_update`.

**Целевая платформа**: веб-браузер на компьютере и телефоне; сервер — тот же контейнер
платформы.

**Цели по производительности**: обновление состояния не позднее 10 секунд после
события; отдача страницы карточек не тяжелее одного обращения к Home Assistant независимо
от числа устройств.

**Ограничения**: токен и адрес Home Assistant знает только адаптер; веб-интерфейс ходит в
дом через адаптер и не знает credentials. Частота опроса ограничена: 5 секунд — это
компромисс между отзывчивостью и нагрузкой на Home Assistant.

**Объём**: 10 комнат, 10 устройств, 11 автоматов в боевом доме; шаблоны карточек,
контекст страницы, одна новая механика в движке.

## Проверка конституцией

*GATE: должен пройти до проектирования.*

| Принцип | Соблюдение |
|---------|-------------|
| I. Event-Driven FSM | Соблюдается. `FSMDefinition`, дебаунс и таймауты не меняются; добавляется только чтение уже принятых значений. Наблюдение состояния идёт через существующий `get_state`. |
| II. TDD/SDD, покрытие | Соблюдается: спека → план → задачи → тесты первыми; новые файлы не ниже 80%. |
| III. Контроль остаётся за пользователем | Соблюдается: решение по карточке остаётся за человеком, а интерфейс лишь показывает его и объясняет. Управление с карточки идёт существующим путём с ролями. |
| IV. Многоуровневая архитектура | Соблюдается: веб-интерфейс обращается к дому через адаптер и к решениям через движок; новых зависимостей между слоями не появляется. |
| V. Манифест — единственный источник конфигурации | Соблюдается: название устройства берётся из манифеста, описание поведения — из заголовков шаблонов. Справочник описаний в коде не заводится. |
| VI. Двухрежимное развёртывание | Соблюдается: при недоступном Home Assistant карточка показывает «нет связи» с последним известным состоянием, а не пустоту. |
| VII. Многоуровневый интерфейс | Соблюдается: веб-интерфейс остаётся одним из интерфейсов; HA Dashboard и CLI не ломаются. |

**Нарушений нет** — Complexity Tracking не заполняется.

### Исходный код (корень репозитория)

```text
src/
├── core/
│   ├── fsm/engine.py          # новое: помнит последнее решение автомата и отдаёт его
│   ├── events/fsm_events.py   # человеческие формулировки причин (словарь рядом с кодами)
│   └── services/state_snapshot.py   # новое: снимок состояний дома с кэшем для интерфейса
├── adapters/ha_adapter.py     # доступ к состояниям для снимка (без новых сетевых путей)
├── webui/
│   ├── app.py                 # контекст страницы: снимок, can_control
│   ├── routes/devices/        # маршруты: снимок карточек, команда с карточки
│   └── templates/
│       ├── index.html         # стили карточек переезжают в partials; страница тоньше
│       └── partials/
│           ├── room_card.html     # переписан
│           ├── device_card.html    # новый: устройство с состоянием и причиной
│           └── sensor_card.html    # новый: датчик с показанием
tests/
├── unit/core/                 # последнее решение автомата, снимок состояний
├── unit/webui/                 # рендеринг карточек на подставных данных
└── integration/                # сквозной путь: событие → карточка
```

**Решение по структуре**: новая логика размещается в существующих модулях; новым
выделен только снимок состояний, потому что это самостоятельная задача с кэшем и
устареванием, а не деталь шаблона. Разметка устройства и датчика уходит в отдельные
партиалы — иначе `index.html` (617 строк) и `room_card.html` продолжат разойтись, о чём
в шаблоне написано прямо.

## Порядок работ (для /speckit-tasks)

1. Последнее решение автомата в движке (+ причины человеческим языком).
2. Снимок состояний дома с кэшем.
3. Контекст страницы: снимок, `can_control`, роли.
4. Партиалы карточек устройства и датчика; перевод на русский; стили.
5. Переключатель состояния на карточке через существующий endpoint команд.
6. Обновление по событиям FSM плюс поллинг-страховка.
7. Проверка вёрстки на узком экране; регенерация контракта; полный прогон.

## Риски и как они снимаются

| Риск | Снятие |
|------|--------|
| Показ причины разойдётся с журналом (тот же дефект, что вчера с формой события солнца) | Причина хранится там же, где пишется в журнал, и выводится из того же словаря; FR-008 закрепляет совпадение отдельной проверкой |
| Частый опрос нагрузит Home Assistant | Один `get_states` на страницу с кэшем 5 секунд; события FSM обновляют карточку без опроса |
| Кэш покажет устаревшее состояние | На карточке видно время чтения; при потере связи — «нет связи» с последним известным значением, а не тишина |
| Кнопка управления покажется пользователю без прав | `can_control` в контексте; endpoint и без прав вернёт 403 — но кнопки не показываются вовсе |
| Вёрстка разъедется на телефоне | Требование FR-018 и отдельная проверка узкого экрана в quickstart |
| Движок начнёт расти в памяти | Хранится одно последнее решение на автомат, без истории; автоматов в доме 11, в пределе — десятки |
