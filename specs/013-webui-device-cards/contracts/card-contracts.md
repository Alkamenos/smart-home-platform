# Контракты: Карточки дома

## 1. Последнее решение автомата (движок)

**Единственный новый контракт вне веб-интерфейса.**

```text
FSMEngine.explain(entity_id) -> Решение | None
```

| Элемент | Тип | Гарантия |
|---------|-----|----------|
| `at` | время UTC | Время принятия решения, не время чтения |
| `outcome` | `on` / `off` / `denied` / `none` | Что сделано |
| `reason_code` | строка или None | Код из `GUARD_DENIAL_REASONS` либо код решения |
| `reason_text` | строка | Формулировка для человека; пустая строка невозможна |
| `trigger` | строка или None | Что вызвало решение |

**Инварианты**:
- решение появляется при каждом переходе **и при каждом отклонении** — «ничего не
  произошло» тоже решением и должно быть видно;
- `explain` для несуществующего автомата возвращает `None`, а не исключение: карточка
  спрашивает про каждый автомат подряд;
- решение одного автомата **не** влияет на другой (кроме `night_light` на своём
  устройстве — это отдельный автомат со своим решением, и карточка их различает).

**Чего контракт не обещает**: истории решений, истории отказов и прогноза. Журнал уже
хранит всё это (`/logs`); хранить вторую копию значит разойтись с первой.

## 2. Снимок состояний дома

```text
StateSnapshot.read() -> Снимок
Снимок: states: {entity_id → Состояние устройства},
        at: время UTC,
        reachable: булево
```

| Гарантия | Почему так |
|----------|-----------|
| Один вызов `get_states` на снимок | Двадцать запросов на страницу — медленно и нагружает дом; `get_states` уже проверен в бою (обнаружение устройств) |
| Повторный чтение в пределах срока жизни кэша не ходит в дом | Пятисекундная жизнь кэша: страница из 10 карточек не делает 10 запросов |
| При недоступном доме `reachable = false`, состояния — последние известные | Молчаливые нули выглядели бы как «всё выключено» (FR-004) |
| Снимок **никогда не вызывает команд** | Снимок — чтение; команда идёт только через endpoint команд с проверкой роли |

## 3. Контекст страницы

Изменения в том, что передаётся шаблону (`webui/app.py`, рендер индекса):

| Ключ | Тип | Обязателен ли | Источник |
|------|-----|---------------|----------|
| `snapshot` | Снимок | да | `StateSnapshot.read()` |
| `decisions` | `{entity_id → Решение}` | да | `FSMEngine.explain` по всем автоматам |
| `lockouts` | `{entity_id → блокировка}` | нет | трекер ручного вмешательства |
| `can_control` | булево | да | роль пользователя (`controller` или выше) |
| `snapshot_at`, `home_reachable` | время, булево | да | снимок |

**Обратная совместимость**: `manifest`, `user_id`, `user_is_admin` сохраняются как были —
остальные экраны их читают.

## 4. Шаблоны карточек

| Партиал | Что показывает | Обязательные элементы |
|---------|----------------|-----------------------|
| `device_card.html` | Название (или идентификатор), состояние, причина, время, выключатель | Состояние и причина — **всегда**, даже если неизвестны: «состояние неизвестно» лучше пустоты |
| `sensor_card.html` | Название датчика по типу, значение с единицей, иконка по типу | Значение с единицей; для движения — «есть движение» / «нет движения», а не `on`/`off` |
| `room_card.html` | Название комнаты, сводка (сколько горит), сетка карточек, кнопки комнаты | Сводка числом словами: «2 из 3 горят» |

**Правила разметки**:
- идентификатор — вторичным шрифтом под названием (FR-014), не заголовком;
- комната в карточке устройства не выводится (FR-016) — она в заголовке над сеткой;
- иконка датчика выбирается по ключу роли (`motion`, `temperature`, `humidity`,
  `contact`), неизвестная роль — нейтральная иконка, **не** термометр (FR-019);
- у датчика, который только читается, выключателя нет вовсе, а не «неработающий»
  (сценарий «устройство без управления»).

## 5. Обновление состояния

| Механизм | Когда | Зачем |
|-----------|-------|-------|
| Событие `fsm_transition` по websocket | Решение принято | Отзывчивость без опроса: карточка меняется сразу |
| Поллинг раз в 5 секунд | Всегда | Страховка: потерянное событие должно обнаруживаться, а не молчать |

**Инвариант**: поллинг не мешает событию. Если оба пришли, применяется более свежая
запись (время `read_at`/`at`).

**Почему не только события**: событие может потеряться (реконнект, рестарт), а карточка
без поллинга покажет состояние, которого уже нет, и владелец будет разбираться с тем,
чего не происходило.

## 6. Команда с карточки

| Пункт | Значение |
|-------|----------|
| Endpoint | Существующий `execute_device_command` (`webui/routes/devices/devices.py:617`) — новый путь не проектируется |
| Проверка прав | Существующая `_require_access_or_403`, роль `controller` |
| Показ кнопок | Только при `can_control` (FR-012) |
| Результат | Ответ команды показывается на карточке: успех — новое состояние, отказ — причина (FR-011) |
| Повторное нажатие | Кнопка блокируется на время выполнения: два клика — две команды, а человек ждёт одного |

## 7. Оформление и вёрстка

| Требование | Как обеспечивается |
|-------------|--------------------|
| Русский язык (FR-017) | Все подписи карточек и разделов; служебные идентификаторы остаются как есть |
| Корректная вёрстка на узком экране (FR-018) | Сетка с переносом в одну колонку, кнопки переносятся отдельной строкой, размеры шрифтов не уменьшаются под телефон |
| Тёмная тема | Существующие переменные темы; карточка не вводит своих цветов |
| Доступность | У выключателя — подпись и `aria-label`; состояние — текстом, а не только цветом |
| Состояния загрузки и ошибки (FR-020) | Карточка показывает «загрузка» при первом заполнении и «нет связи» с кнопкой повтора при недоступности |

## 8. Журнал действий интерфейса

Требование FR-021: интерфейс пишет, что показал и что опрашивал.

| Событие | Уровень | Содержание |
|---------|---------|------------|
| Снимок взят | debug | сколько сущностей, доступен ли дом |
| Карточка отрисована | debug | комната, устройство (без датчиков — их слишком много для журнала) |
| Команда с карточки | info | устройство, команда, результат |
| Дом недоступен | warning | сколько ждали ответа |
