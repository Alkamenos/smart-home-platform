# Модель данных: Карточки дома

## Сущности

### Состояние устройства

Что с устройством прямо сейчас, со стороны дома.

| Поле | Тип | Описание |
|------|-----|----------|
| `entity_id` | строка | Идентификатор в Home Assistant |
| `value` | строка | «on», «off», «21.5», «unavailable» — как прислал дом |
| `unit` | строка или None | Единица измерения из атрибутов (`°C`, `%`) |
| `available` | булево | Доступно ли устройство сейчас |
| `read_at` | время UTC | Когда состояние прочитано — по нему карточка честно говорит «данные на 20:04» |

**Правила**: `unavailable` — это **не** «выключено»: карточка обязана говорить «не
отвечает», иначе молчащее устройство выглядит как исправно выключенное.

### Последнее решение автомата

Что платформа сделала с устройством и почему. Появляется в этом коде впервые: сегодня
решение живёт только в журнале.

| Поле | Тип | Описание |
|------|-----|----------|
| `at` | время UTC | Когда принято решение |
| `outcome` | перечисление | `on` (включено), `off` (выключено), `denied` (отказ), `none` (решение не требовало действия) |
| `reason_code` | строка или None | Код причины из `GUARD_DENIAL_REASONS` либо код решения |
| `reason_text` | строка | Формулировка для человека: «выключено вами вручную», «светло», «нет данных» |
| `trigger` | строка или None | Что вызвало решение: «движение», «закат», «таймер» |

**Правила проверки**:
- `reason_text` обязателен всегда, кроме `outcome = none`: решение без объяснения —
  молчание, а оно дефект по правилу владельца о логах;
- `reason_text` выводится из того же словаря, что и запись в журнале, иначе интерфейс и
  журнал начнут отвечать на один вопрос разными словами;
- хранится **одно** решение на автомат: карточка отвечает на вопрос «почему сейчас», а
  не «что было ночью» — за ночь в журнале всё и так есть.

### Блокировка устройства

Устройство под ручным управлением до указанного времени.

| Поле | Тип | Описание |
|------|-----|----------|
| `until` | время UTC | До какого момента автоматика не трогает устройство |
| `reason` | строка | Откуда блокировка: ручное действие человека |

### Описание поведения

Что поведение делает, словами. Берётся из заголовков шаблонов `src/features/*.yaml`.

| Поле | Тип | Описание |
|------|-----|----------|
| `template` | строка | Имя шаблона: `deco_light` |
| `title` | строка | Человеческое название: «вечерний свет» |
| `summary` | строка | Что делает: «включается по закату, гаснет по отбою» |

**Правило**: справочника описаний в коде не заводится — описание живёт рядом с самим
поведением, иначе оно разойдётся при первой правке шаблона.

## Контекст страницы

Что передаётся шаблону панели.

| Ключ | Тип | Источник | Назначение |
|------|-----|----------|------------|
| `manifest` | манифест | как сейчас | комнаты, устройства, поведения |
| `snapshot` | снимок | новое | состояния устройств и датчиков с временем чтения |
| `decisions` | словарь | новое | последнее решение по каждому автомату |
| `lockouts` | словарь | трекер ручного вмешательства | до какого времени автоматика не трогает |
| `can_control` | булево | роль пользователя | показывать ли кнопки управления |
| `user_is_admin` | булево | как сейчас | существующий признак администратора |
| `snapshot_at` | время UTC | снимок | «данные на …» и признак устаревания |
| `home_reachable` | булево | снимок | «нет связи с домом» вместо пустых значений |

## Связи

```text
Home Assistant ──get_states()──► Снимок состояний (кэш 5 с)
        │                              │
        │                              ▼
        │                        Контекст страницы ──► Карточка комнаты
        │                                                    ├── Карточка устройства
        │                                                    │     состояние · причина · выключатель
        │                                                    └── Карточка датчика
        │                                                          показание · иконка по типу
        ▼
    Движок ──get_state()──► Состояние автомата (ON_HOLD, с какого момента)
        │
        └───последнее решение──► Решение (что, почему, когда) ──► Карточка: «почему»
```

## Поток управления с карточки

```text
Нажатие «выключить»
    │
    ▼
POST /devices/{id}/commands  (существующий execute_device_command)
    │  проверка роли controller
    ▼
Команда в Home Assistant
    │
    ├── успех ──► карточка показывает новое состояние
    └── отказ ──► карточка показывает причину (FR-011), состояние не меняется молча
```
