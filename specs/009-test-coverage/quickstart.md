# Quickstart: проверка фичи Verified Coverage

**Feature**: specs/009-test-coverage | **Дата**: 2026-10-03

Руководство по проверке после реализации. Все сценарии выполняются **без Home Assistant и без сети** — это и есть проверяемое свойство (FR-010). Формы сущностей — в [data-model.md](./data-model.md), соглашения о запуске — в [contracts/verification-funnel.md](./contracts/verification-funnel.md).

---

## Подготовка

```bash
# Зафиксировать состояние ДО изменений: без этого нечего сравнивать
python3 -m pytest tests/ -q --no-cov -p no:cacheprovider | tail -2
# baseline (2026-10-03, коммит 98b5f2c): 1786 collected; 1777 passed; 9 skipped
```

Число 9 пропусков — опорная точка всей фичи: каждое из них должно исчезнуть.

**Инвариант приёмки, а не конкретное число:** `skipped == 0` и `passed == collected`. Абсолютное число выполненных тестов растёт — US2 и US4 добавляют новые тесты, поэтому «выросло ровно на 9» сформулировать нельзя. Проверяется отсутствие пропусков и отсутствие новых падений относительно baseline.

Проверка чистоты рабочего каталога до прогона (позже проверим, что прогоны его не трогают):

```bash
git status --short          # пусто
```

## Сценарий 1. Пропуски сняты и тесты действительно проверяют (US1, FR-001…FR-006, SC-001)

```bash
# Пропусков быть не должно
python3 -m pytest tests/ -q --no-cov -p no:cacheprovider -rs | grep -i skipped
# ожидается: пусто (или только осознанные пропуски с актуальной причиной)
```

```bash
# Число выполненных равно числу собранных
python3 -m pytest tests/ -q --no-cov -p no:cacheprovider | tail -1
# ожидается: N passed, 0 skipped, 0 failed — без «N skipped»
```

**Проверка на «пустые» тесты** — отдельный сценарий, потому что именно такие тесты проходят незаметно:

```bash
grep -rn "pytest.skip" tests/ --include="*.py"
# ожидается: ни одного пропуска внутри теста (см. сценарий 2)
```

**Проверка на тесты без утверждений.** Найденные ранее места должны быть либо исправлены, либо удалены:

```bash
# Было: тест без единого assert, который тем не менее «проверяет» таймаут
grep -rn "contextlib.suppress" tests/integration/test_state_sync.py tests/integration/test_commands.py
```

## Сценарий 2. Самопропускающиеся тесты устранены (US1, FR-003, R-6)

Было: `pytest.skip("No devices available")` стоял **до** всякой проверки прав — тест зелёный, не проверив ничего.

```bash
grep -rn "No devices available" tests/
# ожидается: пусто
```

Проверка вручную: запустить тест разграничения прав на наборе, где устройство гарантированно есть, и убедиться, что он действительно выполняет проверки, а не выходит по пропуску.

## Сценарий 3. Тест не может пройти вхолстую (US1, FR-005)

Ключевая проверка на устойчивость: тест, который «не может упасть», должен перестать существовать в прежнем виде.

```bash
grep -rn "len(devices_after) == len(devices_before)" tests/integration/test_device_sync.py
# ожидается: пусто — тавтомологичное сравнение удалено или заменено настоящей проверкой
```

Проверка «переживает перезапуск» должна пересоздавать приложение, а не делать два чтения подряд. Просмотреть глазами тесты с перезапуском и убедиться, что в каждом создаётся новый экземпляр.

## Сценарий 4. Тесты шифрования исполняются (US1, FR-006, FR-007, SC-005)

```bash
python3 -m pytest tests/unit/core/test_encryption.py -v --no-cov -p no:cacheprovider
# ожидается: тесты собраны и выполнены, число > 0
```

```bash
# Старое место хранения больше не содержит тестов
grep -c "class TestTokenEncryption" tests/security/verify_security.py
# ожидается: 0
```

**Проверка инициализации ключа из окружения** (FR-007) — самоконтроль: тест обязан задавать переменную окружения явно и проверять поведение при её отсутствии. Запуск с пустым окружением должен давать тот же результат, что и с заданной переменной, иначе тест зависит от машины.

## Сценарий 6. Команды интерфейса проверяются (US2, FR-009…FR-013, SC-007)

```bash
python3 -m pytest tests/cli/ -v --no-cov -p no:cacheprovider
# ожидается: тесты всех команд, число > 16 (было только health_check и shell)
```

**Проверка, что тесты идут через штатную точку входа**, а не через внутренние функции: тесты обязаны обращаться к разбору аргументов. Косвенная проверка — ни одного `subprocess` в новых файлах.

**Проверка сети** — ни одна команда не должна требовать внешней системы:

```bash
grep -rn "192.168\|localhost:8123\|http://ha" tests/cli/
# ожидается: пусто
```

**Проверка четырёх ошибочных сценариев (SC-008)** — по одному тесту на каждый:

| Сценарий | Ожидание |
|----------|----------|
| Манифеста нет | ненулевой код, сообщение называет отсутствующий путь |
| Манифест повреждён | ненулевой код, понятное сообщение без трассировки |
| Внешняя система недоступна | сообщение о недоступности, манифест не изменён |
| Неизвестное имя команды | справка со списком команд |

**Проверка отката конфигурации** (FR-012, SC-009): после сбоя команды содержимое файла конфигурации совпадает с исходным.

## Сценарий 7. Одна воронка проверок (US3, FR-016…FR-019, SC-010, SC-011)

```bash
# Что запускает локальная команда
grep -A3 "^test:" Makefile
```

Ключевая проверка — сравнение составов:

```bash
python3 -m pytest tests/ --collect-only -q --no-cov 2>/dev/null | tail -2
python3 -m pytest tests/ --collect-only -q --no-cov --ignore=tests/unit --ignore=tests/contract 2>/dev/null | tail -2
```

Ожидание: разница объяснима объявленными исключениями и только ими.

**Видимость невыполненного** (FR-017): запустить прогон с добавленным искусственным исключением и убедиться, что оно видно в результате с причиной, а не исчезает молча.

## Сценарий 8. Пробелы закрыты (US4, FR-020…FR-026, SC-012…SC-016)

| Проверка | Команда / признак |
|----------|------------------|
| Внешняя система недоступна при команде | тест даёт явный отказ с причиной, не успех и не пустой результат |
| Превышение времени выполнения | результат содержит признак таймауста, а не подавляется |
| Фильтрация списка по правам | тест на **существующем** устройстве; в ассертах нет допуска «пустой список или отказ по несуществованию» |
| Отзыв доступа | прямое обращение к устройству после отзыва даёт отказ, а не данные |
| Конкурентные операции | две одновременные операции не задваивают и не теряют объект |
| Устройство убрано из внешней системы | пропадает из списка, автоматика снята, другие устройства целы |

Проверка на допуск в ассертах — характерная уловка:

```bash
grep -rn "\[200, 404\]\|\[200, 202, 404\]\|\[403, 404\]" tests/
# ожидается: пусто — такие допуски делают проверку прав неразличимой от «устройства нет»
```

3. `pytest tests/` — 0 новых падений относительно baseline; `skipped == 0`, `passed == collected`.
4. `tests/test_webui_playwright.py` — 25 passed.
5. После полного прогона `git status` пуст, каталог данных не изменился.
6. Отметки в задачах спецификаций соответствуют факту (SC-002) — включая `specs/001-device-integration/tasks.md`.
