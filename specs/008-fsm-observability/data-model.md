# Data Model: Observability платформы (008-fsm-observability)

**Вход**: `spec.md` (3 US, 26 FR, 16 SC) + `research.md` (14 решений)
**Дата**: 2026-10-01

Сущности наблюдаемости. Ни одна из них **не хранится** — метрики и снимки живут в памяти процесса и отбрасываются при перезапуске (FR-010).

---

## 1. Метрика (Metric)

Измеримая величина работы платформы. Регистрируется один раз при старте (FR-001) и отдаётся по запросу.

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | `str` | Имя метрики в формате Prometheus, с префиксом семейства и единицей измерения |
| `kind` | `enum(counter, gauge, histogram)` | Тип: счётчик (только растёт), шкала (растёт и падает), гистограмма (распределение) |
| `labels` | `dict[str, str]` | Набор значений, по которым различаются серии метрики |
| `help` | `str` | Человекочитаемое описание, попадающее в ответ |

### Правила

- **R-1. Регистрация один раз**: повторная регистрация того же имени в том же реестре — ошибка, которая переводит сборщик в режим «показатели не собираются» с предупреждением в журнале (FR-008, R-08).
- **R-2. Изоляция реестра**: сборщик принимает реестр измерений; в платформе используется общий, в тестах — отдельный на тест (R-08). Смена реестра не влияет на уже зарегистрированные метрики.
- **R-3. Ограничение кардинальности**: число различных наборов значений на метрику ограничено константой `MAX_LABEL_SERIES_PER_METRIC`. Новый набор сверх лимита не создаёт серию, а учитывается в серии с меткой `__other__`; о переполнении пишется одно предупреждение (FR-005, R-04).
- **R-4. Метрики нулевых значений присутствуют**: счётчики и шкалы появляются в ответе сразу после старта, до первого события (FR-002, SC-004). Достигается предварительным созданием нулевых серий для известных наборов значений либо регистрацией метрики без серий — выбор фиксируется на реализации, требование одно: **отсутствие событий не означает отсутствие метрики**.

### Затрагиваемые метрики

| Метрика | Вид | Значения | Источник данных | FR |
|---------|-----|----------|-----------------|-----|
| `fsm_transitions_total` | счётчик | `fsm_name`, `from_state`, `to_state`, `device` | событие `fsm.transitioned` | FR-003 |
| `fsm_rejections_total` | счётчик | `fsm_name`, `reason` | событие `fsm.rejected` | FR-004 |
| `fsm_states_restored_total` | счётчик | `fsm_name` | событие `fsm.restored` | FR-025 |

| `fsm_stuck_current` | шкала | `fsm_name` | сторож: сколько автоматов зависло сейчас (0 — всё в порядке) | FR-015, FR-016 |

## 2. Снимок состояний (FsmSnapshot)

Состояние всех автоматов на момент одной проверки. Пишется в журнал одной структурированной записью (FR-012, R-12).

| Поле | Тип | Описание |
|------|-----|----------|
| `taken_at` | `str` (ISO-8601) | Время снятия снимка |
| `entries` | `list[FsmSnapshotEntry]` | По одному на каждый зарегистрированный автомат |
| `problem_count` | `int` | Число обнаруженных зависаний в этом снимке |

### 2.1. Запись снимка об одном автомате (FsmSnapshotEntry)

| Поле | Тип | Описание |
|------|-----|----------|
| `entity_id` | `str` | Идентификатор автомата по схеме `{устройство}_{шаблон}_{приоритет}` |
| `device` | `str` | Устройство автомата |
| `state` | `str` | Текущее состояние |
| `entered_at` | `float` (монотонные часы) | Момент входа в состояние; для расчёта длительности пребывания |
| `last_transition` | `str \| None` (ISO-8601) | Настенное время последнего перехода; `None`, если переходов не было |
| `stuck` | `bool` | Пребывание в состоянии дольше допустимого (см. §3) |
| `expected_timeout_sec` | `float \| None` | Допустимое время пребывания, выведенное из описания; `None` — состояние не проверяется |

### Правила

- **R-5. Состояния без таймингованных переходов не считаются зависшими**: `expected_timeout_sec = None` ⇒ `stuck` всегда `False` (R-06).
- **R-6. Снимок не содержит данных прав доступа**: он описывает техническое состояние платформы и не отдаётся в веб-интерфейс; наружу уходят только агрегированные числа (FR-011, R-14).
- **R-7. Пустой снимок — не проблема**: при отсутствии автоматов снимок содержит ноль записей и `problem_count = 0`, проверка считается успешной.

## 3. Допустимое время пребывания (expected_timeout_sec)

Производная величина, а не конфигурация: максимум `timeout_sec` среди переходов, ведущих из текущего состояния автомата (R-06).

| Случай | Значение | Смысл |
|--------|----------|-------|
| Из состояния есть переходы с таймаутом | максимум их `timeout_sec` | автомат обязан покинуть состояние за это время |
| Из состояния есть переходы без таймаутов | `None` | состояние живёт, пока не придёт событие; ждать нечего |
| Из состояния нет переходов вовсе | `None` | конечное состояние; оно по определению стабильно |
| Автомат не зарегистрирован | `None` | нечего проверять |

**Зависание** (`stuck = true`): пребывание в состоянии дольше `expected_timeout_sec` плюс запас `WATCHDOG_STUCK_GRACE_SEC`. Запас покрывает задержку срабатывания таймера и время до следующей проверки.

## 4. Проблема (PlatformProblem)

Обнаруженное отклонение. Редкое событие: публикуется в шину и попадает в показатели только при **появлении** и при **устранении** (FR-015, FR-016, R-12).

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `enum(fsm_stuck, ha_disconnected)` | Вид проблемы |
| `entity_id` | `str \| None` | Автомат; `None` для потери связи |
| `state` | `str \| None` | Состояние зависшего автомата |
| `detected_at` | `str` (ISO-8601) | Время обнаружения |
| `resolved_at` | `str \| None` (ISO-8601) | Время устранения; `None`, пока проблема активна |
| `duration_sec` | `float \| None` | Длительность между обнаружением и устранением; заполняется при устранении |

### Правила

- **R-8. Один активный срез на (вид, автомат)**: повторная проверка зависшего автомата не создаёт новую проблему и не публикует событие повторно (FR-016 — «не продолжает сообщать о несуществующей проблеме»).
- **R-9. Устранение обязательно**: при восстановлении (состояние сменилось, связь вернулась) публикуется событие устранения с `resolved_at`, метрика `*_current` возвращается к нулю (FR-016, SC-010).
- **R-10. Автономный режим не даёт проблему потери связи**: при отсутствии Home Assistant проверка связи не выполняется вовсе, а не выполняется «в минус» (FR-014, R-13).

### Состояния проблемы

```text
        обнаружена                устранена
  (none) ────────────► (active) ────────────► (resolved)
                          ▲                      │
                          └──────────────────────┘
                        обнаружена снова (тот же вид, тот же автомат)
```

## 5. Настройки наблюдаемости (ObservabilitySettings)

Читаются из переменных окружения по образцу работающего `hot_reload_enabled()` (R-07). Схема манифеста не меняется (конституция V).

| Настройка | Переменная | По умолчанию | Поведение при некорректном значении |
|-----------|-----------|--------------|-----------------------------------|
| Сбор показателей | `METRICS_ENABLED` | включено (FR-001) | значение по умолчанию + предупреждение |
| Сторож | `WATCHDOG_ENABLED` | включено | значение по умолчанию + предупреждение |
| Интервал проверок | `WATCHDOG_INTERVAL_SEC` | 60 | значение по умолчанию + предупреждение (ноль и отрицательное недопустимы) |
| Запас на зависание | `WATCHDOG_STUCK_GRACE_SEC` | 30 | значение по умолчанию + предупреждение |
| Порог потери связи | `WATCHDOG_HA_LOSS_SEC` | 300 | значение по умолчанию + предупреждение |

### Правила

- **R-11. Никогда не приводят к сбою старта**: некорректная настройка заменяется безопасным значением, платформа стартует (FR-019).
- **R-12. Ноль и отрицательные интервалы недопустимы**: иначе получился бы бесконечный цикл проверок без сна.
- **R-13. Отдельного порта показателей нет**: `METRICS_PORT` из `deploy/.env.example` удаляется — показатели отдаются с порта платформы (D-2, R-07).

## 6. Связи сущностей

```text
событие перехода (fsm.transitioned) ──┐
событие отказа    (fsm.rejected)    ──┼──► MetricsReporter ──► Метрика
событие восстановления (fsm.restored)┘                          (fsm_transitions_total,
                                                                 fsm_rejections_total,
                                                                 fsm_states_restored_total)

состояние движка ──► FsmSnapshot ──► обнаружение ──► PlatformProblem ──► Метрика
     (get_all_states)   (журнал)       (сравнение)     (шина, один раз)   (fsm_stuck_*,
                                                     на появление          ha_connection_lost)
                                                     и устранение)
```

**Источник истины один**: состояние движка. Ни метрики, ни снимки, ни проблемы не являются источником состояния автомата — они только читают его (FR-001, FR-013: сбор показателей не влияет на работу автоматики).
