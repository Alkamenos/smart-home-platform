# HANDOFF — Платформа умного дома (Дом Леонида)
**Дата:** 01 сентября 2026 г.
**Статус:** v1.2.0 — Система расширенного логирования внедрена и работает.
**Версия:** 1.2.0

## 1. Цель и требования
Строим data-driven платформу умного дома поверх Home Assistant как **продукт для тиражирования** по инстансам.
* **Требования:** лёгкая модификация; миграция с легаси без поломок; настройка через UI (без YAML); учёт внешних условий; распознавание источника команды (физический выключатель / Алиса / автоматика) для предотвращения конфликтов.
* **Семантика:** ручное управление всегда реально; флаги фич выключают только автоматику; теневой режим (shadow) — лог вместо исполнения; блокировки (override) 60-120 мин после ручного вмешательства.
* **Логирование (v1.2.0):** единая система с управлением уровнями через дашборд, буфер решений, детализация «что/когда/почему/кто».

## 2. Окружение и стек
* **Железо и ПО:** HA на Raspberry Pi 4, аддон VS Code (git), репо в `/config/.platform`.
* **Интеграции:** Zigbee (Zigbee2MQTT) + Wi-Fi + Яндекс Станции.
* **Деплой:** исходники в `ha/pyscript/` и `features/*/` собираются билдом в единый `/config/pyscript/manifest_loader.py`.

## 3. Архитектура и ключевые решения
* **Манифест инстанса** (`instances/leonid/manifest.yaml`) — единый источник правды. Группы света и настройки в `features.groups`.
* **FSD-структура фич:** `features/<id>/` содержит 4 артефакта: `schema` (Pydantic), `helpers`, `ui` (карточки), `decide` (логика). У контроллеров есть `runtime.py`.
* **Реестр фич (`_FD_REGISTRY`):** вместо жёстких цепочек. Приоритет = порядок регистрации. Причина решения = имя фичи.
* **Override Manager:** слушает `state_changed`, отличает «команду платформы» от внешней и ставит временный блок. Реализован **опросно** (не глобальным event_trigger) из-за нагрузки на RPi4.
* **Разделение:** HA-native (helpers, Lovelace) для UI; `pyscript` для логики.
* **Система логирования (v1.2.0):**
  - Диспетчер `log_event()` в `manifest_loader.py` (до всех контроллеров).
  - Кэш уровней по доменам (обновляется по `@state_trigger` на `input_select.loglevel_*` + раз в минуту).
  - Кольцевой буфер решений (50 записей) → `sensor.platform_decisions`.
  - Управление уровнями через дашборд (helpers `input_select.loglevel_*`).

## 4. Критичные ограничения Pyscript (ВАЖНО!)
* **Нет общего namespace** между файлами → склейка через `./shp build` обязательна.
* **`@time_trigger("period=30")` не парсится** → используем `@time_trigger("startup")` + бесконечный цикл `task.sleep(30)`.
* **`pyscript.reload` дублирует фоновые циклы** → после изменений логики **всегда делаем полный перезапуск HA**.
* **Состояние climate** = `hvac_mode` (cool/heat/off), а НЕ `on/off` → используем `_clim_is_on`.
* **Глобальные `@event_trigger("state_changed")`** = спам и перегрев event loop → используем только целевые `@state_trigger` по списку entity.
* **Генератор-выражения не поддерживаются** → используем списковые включения (list comprehensions) и обычные циклы.

## 5. Текущее состояние (Что работает)
### Освещение (12 групп + vlight-слой)
* **vlight-слой:** виртуальные `input_boolean.vlight_<id>` для кнопок/Алисы/дашборда. Синхронизация с реальными лампами.
* **Расписание:** закат/время/не включать + окна вкл/выкл.
* **Движение:** ортогонально расписанию. Глобальные таймауты + свои для санузла (запрет авто-включения ночью). Keepalive для table.
* **Party-роли:** не включает выключенное, держит включённое до рассвета.
* **Доп. фичи:** имитация присутствия, цветовая температура (кривая день→ночь), сезонные варианты, подсветка выключателей, RGB-ночник.
* **Логирование:** решения по группе (желаемое + why из voters), ручные команды, override вкл/выкл, ночник, восстановление профиля.

### Климат (4 зоны)
* Конвекторы + AC с deadband. Двунаправленная оценка (heat/cool всегда, без `auto`).
* **Safety:** зимний блок AC с голосовым предупреждением через Яндекс; осушение летом при влажности; вентилятор санузла.
* Координация с рекуператорами (free-heat: не дублировать нагрев уличным воздухом).
* **Логирование:** нагрев/охлаждение по зоне (уставка, текущая, дельта), safety (lockout AC, осушение), free-heat с вентиляцией, мёртвые датчики.

### Вентиляция (2× Vakio Base Smart)
* Пресеты: приток/вытяжка/рекуперация (зима/лето, макс, ночной). Скорость через `percentage`.
* Профили: boost с авто-выклом, зимняя пауза, free heating/cooling, away-режим.
* Open-doors: сейчас mock через `input_boolean`, реальные датчики — в планах.
* **Логирование:** смена режима/пресета (расписание, влажность, boost, ночь, двери), авто-выключение boost.


### Система логирования (v1.2.0)
* **Домены:** `platform`, `lighting`, `climate`, `ventilation`, `sensor_health`, `covers`.
* **Уровни:** `Выкл`, `Ошибки`, `Предупреждения`, `Инфо`, `Отладка`.
* **Управление:** helpers `input_select.loglevel_*` (с дашборда администратора).
* **Формат строк:** `[<домен>][<УРОВЕНЬ>] <событие> | why=<причина> | src=<источник> | <ключи>`.
* **Буфер решений:** `sensor.platform_decisions` (атрибут-список, новые сверху).
* **Семантика:** уровень «Выкл» глушит домен; смена уровня без рестарта; логирование НЕ меняет поведение.
### Sensor Health и Дашборды
* **Датчики:** детект `unavailable` + низкая батарея. Агрегированный список покупок (тип и кол-во батареек из манифеста).
* **Логирование:** потеря/восстановление датчика, низкая батарейка.
* **Дашборды:** 3 штуки (home, settings, admin), генерируются из манифеста. Mushroom cards, conditional-карточки, цельные vertical-stack-in-card.
* **Вкладка «📝 Журнал решений»:** последние 50 решений платформы с деталями (время, домен, решение, причина).

## 6. Как работать с кодом (CLI `./shp`)
Все операции через CLI в корне репо:
```bash
# Основной цикл
./shp validate          # Валидация манифеста
./shp build             # Сборка pyscript (склейка в manifest_loader.py)
./shp deploy            # Деплой артефактов

# Работа с UI и хелперами
./shp helpers --apply   # Провизия input_boolean/select/datetime
./shp dashboards        # Генерация дашбордов
./shp cleanup           # Удаление дублей хелперов (если появились _2, _3)

# Создание нового
./shp new feature <id>  # Снизпет новой фичи
./shp new instance <id> # Снизпет нового инстанса
./shp new group <id>    # Снипет новой группы света
```

## 7. Диагностика и логирование
### Логи
- Настройки → Журнал (фильтры по доменам: `[platform]`, `[lighting]`, `[climate]`, `[vent]`, `[health]`).
- Формат: `[<домен>][<УРОВЕНЬ>] <событие> | why=<причина> | src=<источник> | <ключи>`.
- Источник (`src`): `автоматика`, `ручное`, `Алиса-внешний`, `таймер`, `датчик`.

### Сервисы отладки
- `pyscript.light_debug` — показывает решения и причины по освещению.
- `pyscript.climate_debug` — диагностика климата (уставки, дельта, действия).
- `pyscript.vent_debug` — диагностика вентиляции (режимы, пресеты, boost).
- `pyscript.light_capabilities` — выгружает возможности в сенсор.

### Журнал решений
- Админ-дашборд → вкладка «📝 Журнал решений».
- Последние 50 решений с деталями: время, домен, решение, причина, источник.
- Данные из `sensor.platform_decisions` (атрибут `decisions`).

### Управление уровнями логирования
- Админ-дашборд → вкладка «📝 Логирование».
- Выпадающие списки для платформы и каждой фичи.
- Уровень «Выкл» полностью отключает логи домена.
- Смена уровня применяется мгновенно (без рестарта).

## 8. Следующие шаги (Roadmap)
Продуктовые фичи: «сопровождение» светом (первая внешняя фича через реестр); полив (учёт дождя, влажности почвы, календаря).

Документация: автогенерация docs по фичам.

## 9. Известные проблемы и нюансы
Mushroom cards: требуют прописки resources в configuration.yaml (url: /hacsfiles/lovelace-mushroom/mushroom.js).
Теневой режим (Shadow): если автоматика только логирует, но не управляет светом, выключите тень:
```bash
curl -s -X POST -H "Authorization: Bearer $HA_TOKEN" -H "Content-Type: application/json" \
  -d '{"entity_id": "input_boolean.lighting_shadow_mode"}' \
  "$HA_URL/api/services/input_boolean/turn_off"
  ```

Дубли хелперов: если в HA появились _2, _3, используйте ./shp cleanup.
