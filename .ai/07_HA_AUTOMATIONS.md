# Автоматизации Home Assistant: что там живёт и что из этого нужно платформе

**Источник:** просьба владельца 2026-10-15 — «проанализировать автоматизации в HA,
попытаться достать оттуда логику и записать её в отдельном документе, чтобы брать идеи
для того, что нам предстоит реализовать».

**Статус документа:** ◐ Первый проход. Инвентарь собран из Home Assistant (состояния,
идентификаторы, время последнего запуска); **полные конфигурации автоматизаций этой
версией API не отдаются** (`config/automation/list` → `unknown_command`), поэтому логика
выведена из имён, включённости и времени запуска. Чтобы достать точные триггеры и
условия, нужен файл `automations.yaml` из каталога конфигурации HA — см. «Как углубить».

## Что есть в доме

- **83 автоматизации**, из них **включено 18**, выключено 65.
- У всех есть идентификатор (UI-редактируемые), но конфигурация через API недоступна.
- Выключенные 65 — это в основном исторический мусор прошлых версий: он же кандидат
  на чистку (см. BACKLOG B77, интерфейс чистки).

## Что из этого стоит реализовать у нас (идеи)

1. **Пожарная безопасность целиком** (`dym`): сейчас платформа знает только аварийный
   флаг штор. Логика «дым → свет по путям эвакуации, шторы открыть, сообщить» — наша.
2. **Уведомления и голос** (`zvonok_vorota`, `gromkost_na_iandeks_stantsiiakh`): платформа
   умеет только вести журнал. Нужен канал «сказать владельцу» (колонки, телеграм).
3. **Учёт энергии** (`elektroenergiia_tarif`): тарифы и «сколько потребил дом» — из наших
   же данных (вкл/выкл + мощность), без новой интеграции.
4. **Кухня и настольная лампа** (`svet_nad_rabochei_poverkhnostiu`, `nastolnaia_lampa`):
   привести эти приборы в манифест — тогда у них будет то же правило поведения, что у
   остального света (движение, тихие часы, возврат к автоматике).
5. **Разделение сфер** (важно записать, чтобы не спорить): HA владеет **флагами и
   режимами дома** (`my_doma`, `zima`, `sleep_mode`, тарифы), платформа — **приборами**
   (свет, шторы, климат, вентиляция). Пересечение по свету (`na_ulitse_*`,
   `svet_v_kabinete`) надо убрать в одну сторону: либо HA, либо платформа.

## Как углубить (следующий шаг)

- Получить `automations.yaml` из каталога конфигурации Home Assistant — тогда по каждой
  автоматизации будут точные триггеры, условия и действия, и документ превратится в
  «карту логики дома» с построчным разбором.
- Собрать из журнала HA (`/var/log/homeassistant`) трассировки запусков за неделю: это
  покажет, какие автоматизации реально работают, а какие — мёртвый груз (кандидаты на
  чистку, BACKLOG B77).
