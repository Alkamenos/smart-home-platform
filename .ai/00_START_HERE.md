Этот файл — **главная точка входа** для ИИ-ассистента. Он содержит пошаговый алгоритм выполнения любой задачи в проекте.

## ⚡ Быстрый старт (5 минут)

Перед началом ЛЮБОЙ задачи выполни эти шаги:

1. **Прочитать этот файл** ← Ты сейчас здесь ✅
2. **Изучить `.ai/03_ROADMAP.md`** — найти свою задачу
3. **Прочитать `.ai/04_RULES.md`** — запомнить ограничения

# 2.2 Писать тесты СРАЗУ, не откладывать

### Шаг 3: Финальная проверка (ОБЯЗАТЕЛЬНО!)

```bash
# 3.1 Запустить ВСЕ проверки качества:
.ai/scripts/run_checks.sh

# 3.2 Если проверки падают (exit code 1):
❌ НЕ КОММИТЬ!
→ Исправить все проблемы
→ Запустить снова
→ Коммитить только когда exit code 0
```

**Что проверяет run_checks.sh:**
- ✅ Tests (pytest) — все тесты должны проходить
- ✅ Coverage — минимум 80%
- ✅ Type checking (mypy) — строго
- ✅ Linting (ruff) — E, F, W, I, N, UP, B, A
- ✅ Formatting (ruff format)
- ✅ Documentation coverage (interrogate)

**Чек-лист Шага 3:**
- [ ] `run_checks.sh` выполнен успешно ✅
- [ ] Все тесты проходят
- [ ] Покрытие >= 80%
- [ ] Нет ошибок mypy
- [ ] Нет линтер-warnings

### Шаг 5: Коммит

```bash
# Создать коммит (pre-commit хук автоматически запустит проверки):
git commit -m "type(scope): description"
```

**Pre-commit хук ПРОВЕРЯЕТ ВСЕГДА:**
- ✅ Ruff lint
- ✅ Ruff format
- ✅ MyPy type checking
- ✅ Проверка .gitignore
- ✅ Синхронизация ROADMAP

**Формат сообщения коммита:**
```
type(scope): description

[optional body]

[optional footer]
```

**Types:** `feat`, `fix`, `refactor`, `test`, `docs`, `chore`
**Scope:** `core`, `adapters`, `manifest`, `cli`, `tests`, `docs`, `webui`

**Пример:**
```
feat(core): Add EventRouter for sensor-to-FSM mapping

- Build sensor-to-FSM mapping from manifest
- Route motion_detected/motion_cleared events
- Add comprehensive unit tests

Closes #42
```

**Чек-лист Шага 5:**
- [ ] Сообщение коммита соответствует формату
- [ ] Один коммит = одна логическая задача
- [ ] Pre-commit хук прошел успешно

---

### Шаг 6: Пуш

```bash
# Сделать пуш (pre-push хук автоматически запустит полные проверки):
git push origin main
```

**Pre-push хук ПРОВЕРЯЕТ ВСЕГДА:**
- ✅ Запуск `run_checks.sh` (тесты + покрытие + линтер)
- ✅ Актуальность ROADMAP
- ✅ Наличие незакоммиченных изменений

**Важно:** Pre-push — последний рубеж защиты. Даже если pre-commit был обойдён, pre-push не даст отправить код с упавшими тестами.

**Чек-лист Шага 6:**
- [ ] Pre-push хук прошел успешно
- [ ] Код отправлен в удалённый репозиторий

## 🎯 Режимы работы

### Стандартный режим (рекомендуется) — ВСЕГДА включены проверки

```bash
git commit -m "feat: ..."
git push
```
✅ Статические проверки при коммите, полные проверки при пуше (теперь по умолчанию!)

### Быстрая разработка (только для черновиков)

Если нужно обойти проверки (НЕ рекомендуется):

```bash
# Временное отключение хуков
git config --unset core.hooksPath
git commit -m "WIP: ..."
git push
# Вернуть хуки обратно
git config core.hooksPath .githooks
```
⚠️ Используйте только для промежуточных коммитов в процессе разработки

### Строгий режим (перед релизом)

```bash
.ai/scripts/run_checks.sh  # Убедиться что всё проходит
git commit -m "feat: ..."
git push
```
✅ Максимальная гарантия качества

## 🛑 Что делать если...

### Тесты падают
1. ❌ Не продолжать работу
2. Исправить тесты
3. Запустить снова
4. Если не можешь исправить → записать в Known Issues

### Нашла баг в существующем коде
1. Записать в `.ai/01_PROJECT_STATE.md` → Known Issues
2. Добавить задачу в `.ai/03_ROADMAP.md` → Technical Debt
3. Не исправлять, если это не часть текущей задачи

### Pre-commit хук не сработал
```bash
# Проверить настройку:
git config core.hooksPath  # Должно быть .githooks

# Если не настроен:
./.ai/scripts/setup_hooks.sh

# Запустить проверки вручную:
.ai/scripts/run_checks.sh

# Хуки теперь работают ВСЕГДА — флаг AI=1 больше не нужен!
```

### Нужна информация, которой нет в файлах
1. Спросить пользователя
2. Не угадывать и не предполагать
3. После получения ответа → обновить соответствующий файл в `.ai/`

```bash

# Временно отключить хуки (НЕ рекомендуется)

```
