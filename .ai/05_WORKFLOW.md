# AI Workflow

Этот документ описывает пошаговый алгоритм работы ИИ над задачами проекта.

## Перед началом ЛЮБОЙ задачи

### Шаг 1: Контекст (5 минут)

1. Прочитать `.ai/00_CONTEXT.md` — понять структуру harness
2. Прочитать `.ai/01_PROJECT_STATE.md` — что работает сейчас
3. Прочитать `.ai/04_RULES.md` — запомнить ограничения
4. Прочитать `.ai/03_ROADMAP.md` — найти свою задачу в roadmap

### Шаг 2: Понимание задачи (10 минут)

5. Прочитать `.ai/02_ARCHITECTURE.md` — если задача затрагивает архитектуру
6. Изучить существующий код, связанный с задачей:
   - Найти файлы, которые нужно изменить
   - Понять текущую логику
   - Найти существующие тесты для этого функционала
7. Проверить `01_PROJECT_STATE.md` → Known Issues — есть ли связанные проблемы

### Шаг 3: Планирование

8. Сформулировать план действий (мысленно или в комментарии)
9. Определить, какие файлы нужно создать/изменить
10. Определить, какие тесты нужно написать
11. Оценить риски — может ли изменение сломать что-то другое?

## Во время работы

### Шаг 4: Реализация

12. Делать маленькие атомарные изменения
13. После каждого значимого изменения запускать:
    ```bash
    .ai/scripts/run_checks.sh
    ```
14. Если проверки падают — **исправить ДО продолжения работы**
15. Писать тесты **СРАЗУ**, не откладывать

### Шаг 5: Документирование

16. Обновлять docstrings при изменении API
17. Добавлять комментарии для сложных алгоритмов
18. Если нашел баг/долг — добавить в `.ai/03_ROADMAP.md` → Technical Debt
19. Если нашел новую проблему — добавить в `.ai/01_PROJECT_STATE.md` → Known Issues

### Шаг 6: Тестирование

20. Написать тесты **до** или **одновременно** с кодом
21. Запустить тесты для измененных файлов:
    ```bash
    pytest tests/test_<filename>.py -v
    ```
22. Убедиться, что все тесты проходят

## После завершения задачи

### Шаг 7: Финальная проверка

23. Запустить **ВСЕ** проверки:
    ```bash
    .ai/scripts/run_checks.sh
    ```
24. Проверить руками:
    - [ ] Код читается легко
    - [ ] Нет дублирования
    - [ ] Имена переменных осмысленные
    - [ ] Нет magic numbers
    - [ ] Все функции имеют type hints и docstrings

### Шаг 8: Обновление документации

25. Обновить `.ai/01_PROJECT_STATE.md`:
    - Что было сделано
    - Какие файлы изменились
    - Текущий статус
    - Обновить дату последнего обновления

26. Обновить `.ai/03_ROADMAP.md`:
    - Отметить завершенные задачи `[x]`
    - Обновить статус фазы
    - Добавить новые задачи, если появились
    - Обновить Technical Debt, если нужно

27. Если задача значимая — запустить синхронизацию:
    ```bash
    make sync-roadmap
    ```

### Шаг 9: Коммит

28. Создать осмысленное сообщение коммита (см. `04_RULES.md`)
29. Один коммит = одна логическая задача
30. Не смешивать рефакторинг и новые фичи

## Что делать, если что-то не так?

### Тесты падают
1. Не продолжать работу
2. Исправить тесты
3. Запустить снова
4. Если не можешь исправить — записать в Known Issues

### Нашла баг в существующем коде
1. Записать в `01_PROJECT_STATE.md` → Known Issues
2. Добавить задачу в `03_ROADMAP.md` → Technical Debt
3. Не исправлять, если это не часть текущей задачи

### Нужна информация, которой нет в файлах
1. Спросить пользователя
2. Не угадывать и не предполагать
3. После получения ответа — обновить соответствующий файл в `.ai/`
